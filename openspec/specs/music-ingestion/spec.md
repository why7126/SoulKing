# Music-Ingestion Specification

## Purpose

定义「音乐入库」能力：从本地目录递归扫描符合格式的音频文件，或通过上传接口接收多个音频文件，将其写入对象存储并在曲库中建立或关联歌曲与专辑记录；同时提供一次操作范围内的进度与跳过说明查询能力。本规范仅描述当前已实现行为。

## Requirements

### Requirement: 目录扫描入口与路径校验

客户端可请求对某一目录执行入库扫描；若请求体未指定目录，则使用应用配置的默认导入根路径。若目标路径不存在或不是目录，本次请求应当被拒绝并返回错误说明，且不得对该路径执行扫描逻辑。

#### Scenario: 合法目录触发扫描

- **GIVEN** 目标路径存在且为目录
- **WHEN** 客户端发起目录扫描请求
- **THEN** 服务端在完成整次扫描循环前保持处理该请求
- **AND** 响应中包含本次扫描的任务标识、任务状态、计数汇总及跳过明细列表（无跳过时可为空列表）

#### Scenario: 非法路径被拒绝

- **GIVEN** 请求指定的路径不存在，或存在但不是目录
- **WHEN** 客户端发起目录扫描请求
- **THEN** 服务端返回表示请求无效的错误响应
- **AND** 不对该路径启动扫描入库流程

#### Scenario: 无候选音频文件时仍会结束

- **GIVEN** 目标目录存在且合法，但其中不存在后缀符合允许列表的音频文件
- **WHEN** 客户端发起目录扫描请求
- **THEN** 服务端正常返回响应，计数可为零，跳过明细为空

### Requirement: 上传文件入库入口

客户端可通过多部分表单一次提交多个音频文件；服务端按提交顺序逐个尝试入库，并在响应中汇总成功与跳过数量及跳过原因列表。响应中的任务标识为零，且不依赖持久扫描任务记录承载本次统计。

#### Scenario: 多文件上传尝试入库

- **GIVEN** 客户端在一次请求中附带多个文件，且其中若干文件的后缀属于允许列表
- **WHEN** 服务端处理该请求
- **THEN** 仅对后缀符合允许列表的文件逐一执行入库尝试
- **AND** 响应中包含本次处理的数量汇总及每项跳过的人类可读原因（若有跳过）

#### Scenario: 上传请求中无任何符合后缀的文件

- **GIVEN** 客户端发起上传入库请求，但没有任何附件的后缀属于允许列表（或列表为空）
- **WHEN** 服务端处理该请求
- **THEN** 响应中计数为零或均为零，且不创建持久扫描任务记录（任务标识为零）

### Requirement: 音频格式白名单

仅处理后缀属于约定集合的音频文件；比较后缀时忽略大小写。不符合后缀的文件在目录扫描中被跳过，在上传入口中不参与入库尝试。

#### Scenario: 后缀不在白名单则被忽略

- **GIVEN** 目录中存在后缀不在允许集合内的文件，或上传请求中含有此类文件
- **WHEN** 执行目录扫描或上传入库
- **THEN** 这些文件不会进入单文件入库尝试流程

### Requirement: 按内容去重

若曲库中已存在与待入库文件内容相同的记录（以文件内容的摘要值与文件字节长度共同判定一致），则不得新增一条重复的音频文件记录；该次尝试应当被记为跳过，并附带可读的跳过说明（说明中可包含已有对象的存储位置等与实现一致的信息）。

#### Scenario: 重复内容跳过入库

- **GIVEN** 待入库文件的摘要与长度与曲库中已有某条音频文件记录一致
- **WHEN** 执行该文件的单文件入库流程
- **THEN** 该文件被记为跳过而非新增
- **AND** 跳过原因中说明曲库已存在相同内容

### Requirement: 单文件入库管线

对每个进入入库流程的文件，服务端应当：计算内容摘要；从文件中读取时长与标签等信息；根据标签中的艺人名在已有艺人库中查找是否可关联主艺人；获取或创建专辑记录；确定目标歌曲并向对象存储写入音频对象；在曲库中创建对应的音频文件记录并与歌曲关联。若在写入曲库前已向对象存储写入对象且后续发生错误，应当尝试删除已写入的对象；删除尝试失败时错误可被吞掉而不向上抛出。

#### Scenario: 成功路径写入存储与曲库

- **GIVEN** 文件通过内容去重检查且后续步骤未发生错误
- **WHEN** 完成单文件入库流程
- **THEN** 对象存储中存在对应音频对象，曲库中存在与该歌曲关联的新音频文件记录

#### Scenario: 写入曲库失败后清理已上传对象

- **GIVEN** 已向对象存储上传成功，但在写入或提交曲库时发生冲突或其它错误
- **WHEN** 服务端处理该错误
- **THEN** 应当尝试将该对象从对象存储中删除

#### Scenario: 单文件环节返回未成功时在批量流程中的归类

- **GIVEN** 目录扫描或上传批量流程中某一文件的单文件入库返回未成功（含重复内容、数据库冲突或其它异常）
- **WHEN** 服务端汇总本次批量结果
- **THEN** 该文件计入跳过次数并写入跳过明细，而不是单独增加一类与「跳过」并列的全局失败计数

### Requirement: 入库时歌曲标题与文件名

用于匹配或新建歌曲标题的字符串来自源文件名去掉扩展名后的主干（上传时使用原始文件名；目录扫描时使用磁盘上的文件名）。该行为独立于标签中常见的歌曲标题字段是否另有取值。

#### Scenario: 标题取自文件名主干

- **GIVEN** 源文件名为 `曲目名.flac`（或上传时提供的等价文件名）
- **WHEN** 为该文件定位或新建一首歌曲以挂载音频
- **THEN** 用于歌曲标题匹配的字符串为 `曲目名`，而不使用标签内嵌歌曲标题字段作为该步骤的输入

### Requirement: 主艺人关联范围

标签中解析出的艺人名仅在曲库中已存在对应艺人记录时可关联为主艺人；系统不因本次入库自动创建新的艺人记录。若无法关联主艺人，仍可新建歌曲，且不得将此次入库与「仅有相同歌曲标题且无主艺人」的已有歌曲自动合并为同一首。

#### Scenario: 艺人仅在已存在时关联

- **GIVEN** 标签中的艺人名在曲库中尚无对应艺人记录
- **WHEN** 完成该文件的入库
- **THEN** 新建歌曲可以不携带主艺人标识，且不会因标题相同而并入另一条无主艺人的同名歌曲

#### Scenario: 已存在主艺人时复用歌曲并追加格式

- **GIVEN** 标签解析得到的主艺人可在曲库中匹配到，且已存在若干首歌曲满足相同歌曲标题（忽略大小写）且主艺人相同
- **WHEN** 执行入库
- **THEN** 在其中一首歌曲下追加新的音频文件记录而非新建一首歌曲
- **AND** 若存在多条上述候选歌曲：当入库文件具备时长信息且存在至少一首候选歌曲的时长与之相差不超过固定阈值时，在符合条件的候选中选择时长最接近的一首；当入库文件不具备时长信息、或没有任何候选落在该阈值内时，则在候选中选择实现所确定的一首（实现上对候选按记录标识升序取第一条）

### Requirement: 目录扫描的任务记录与统计

一次目录扫描会在持久存储中创建一条扫描任务记录，包含扫描根路径与运行状态。在成功遍历目录并完成扫描循环后，任务状态为已完成，并写入统计到的已扫描文件数、成功入库数与跳过数。若任务创建之后判定根路径不存在或不是目录，则任务状态为失败且统计为零（对外 HTTP 入口在调用前已校验路径时，通常不会出现该分支）。上传入库路径不在持久存储中创建同类任务记录，响应中标明的任务标识为零。

#### Scenario: 目录扫描成功完成时产生任务与统计

- **GIVEN** 目录扫描请求指向合法目录且扫描循环执行完毕
- **WHEN** 客户端查看本次请求的响应
- **THEN** 存在一条对应的扫描任务记录，任务状态为已完成，并带有扫描与入库汇总计数

#### Scenario: 上传入库不创建扫描任务记录

- **GIVEN** 客户端仅使用上传入口完成一次或多文件入库
- **WHEN** 服务端返回结果
- **THEN** 响应中的任务标识为零

### Requirement: 进程内进度与重置

服务端维护最近一次目录扫描或上传入库过程填充的进度快照（是否进行中、总数、已扫描数、成功数、跳过数、开始时间、跳过明细）。客户端可读取该快照，也可将进度重置为初始空状态。

#### Scenario: 读取进度

- **GIVEN** 刚完成或正在进行一次扫描或上传入库（在同一服务进程内）
- **WHEN** 客户端请求进度接口
- **THEN** 返回与当前快照一致的进度字段与跳过明细

#### Scenario: 重置进度

- **GIVEN** 客户端调用重置接口
- **WHEN** 请求成功处理
- **THEN** 进度快照恢复为未进行中的初始状态，计数清零，跳过明细为空

### Requirement: 目录扫描的同步执行

目录扫描在服务端处理扫描请求的调用栈内同步执行至结束；客户端在收到响应前，扫描循环不会提前返回。

#### Scenario: 请求阻塞至扫描结束

- **GIVEN** 客户端发起目录扫描请求
- **WHEN** 目录下存在大量符合格式的文件
- **THEN** 直至全部候选文件处理完毕，服务端才返回该请求的响应

### Requirement: 目录扫描时关联侧车 LRC 文件

在目录扫描流程中，当某一音频文件成功完成单文件入库后，服务端 SHALL 在同一目录中查找与音频文件主文件名相同、扩展名为 `.lrc`（大小写不敏感）的侧车文件。若找到且可读，则将该 LRC 关联到该次入库所挂载的歌曲标识，并执行「每曲一条有效 LRC」替换逻辑（见 `song-lyrics` 规格）。侧车关联失败（如读取错误、超大文件）SHALL 记入本次扫描的跳过明细或等价人类可读日志，且 MUST NOT 导致已成功入库的音频回滚。

侧车 LRC 文件 MUST NOT 计入「已扫描音频文件数」的分母枚举（扫描前总数仍仅统计音频后缀）；是否单独统计「已关联歌词数」由实现决定，不作为本要求的验收条件。

#### Scenario: 音频与同主文件名 LRC 同时存在

- **GIVEN** 目录中存在 `曲目.flac` 与 `曲目.lrc`，且 `曲目.flac` 本次扫描成功入库并挂载到歌曲 S
- **WHEN** 目录扫描处理该音频文件之后
- **THEN** `曲目.lrc` 被关联到歌曲 S
- **AND** 歌曲 S 可通过歌词读取接口获得该 LRC 内容

#### Scenario: 仅有音频无侧车 LRC

- **GIVEN** 目录中存在 `曲目.flac` 但不存在同主文件名的 `.lrc`
- **WHEN** 该音频成功入库
- **THEN** 不创建 LRC 记录
- **AND** 歌曲仍正常存在于曲库

#### Scenario: 音频入库被跳过时不关联 LRC

- **GIVEN** 目录中存在 `曲目.flac` 与 `曲目.lrc`，但 `曲目.flac` 因内容重复等原因被跳过
- **WHEN** 目录扫描完成该文件处理
- **THEN** 不得将 `曲目.lrc` 关联到任何新歌曲

#### Scenario: 侧车 LRC 损坏或超限

- **GIVEN** 音频已成功入库，但侧车 `.lrc` 超过大小上限或无法读取
- **WHEN** 服务端尝试关联侧车
- **THEN** 音频入库结果保持不变
- **AND** 跳过明细或日志中包含可读的失败原因

## Notes

- 默认导入根路径由应用配置提供；请求体中的目录字段可覆盖该默认值。
- 允许的后缀集合由应用侧固定配置；扩展名过滤行为以当前实现为准。
- 上传入口在逐文件处理间隙对异步调度短暂让步，不改变「单次目录扫描请求同步完成」的结论。
- 对外目录扫描接口在调用扫描逻辑前校验路径，故扫描任务处于「已创建但根路径立刻不可用」的失败分支在正常 HTTP 使用中极少出现。

## Known Gaps

以下行为未以强制性语句写入正文，或仅部分覆盖：

- **进度隔离**：多个并发扫描或上传请求共用同一进程内进度快照，可能互相覆盖。
- **扫描任务结束时间**：持久任务记录可能包含「结束时间」类字段，完成路径未必写入。
- **候选文件总数与已扫描数**：响应中的总数来自扫描前枚举，任务统计来自遍历；二者在目录内容变化时未必相等。
- **前端交互**：管理界面如何触发扫描与上传、是否轮询进度，需对照静态前端单独描述。
- **对象存储删除失败**：清理已上传对象时删除失败不会阻止流程返回跳过或错误说明。
