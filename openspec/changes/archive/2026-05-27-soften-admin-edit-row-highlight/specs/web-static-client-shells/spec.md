## MODIFIED Requirements

### Requirement: 后台列表区分正在播放与编辑选中且播放态与前台一致

后台歌曲管理页表格中，客户端 MUST 使用可区分的行态表示「当前正在播放」（由 `currentPlayIndex` 与 `playQueue` 驱动，如 `is-playing`）与「当前编辑上下文选中」（打开编辑抽屉或点击行编辑所对应歌曲，如 `is-active`）。正在播放行视觉强度 MUST 不低于前台音乐库播放行（同色阶意图：紫系背景、冻结列各 `td` 实色背景、无透底）。编辑选中行 MUST 使用明显弱于播放行的视觉（背景色对比低于播放行，且不得对行内每个数据列重复施加左侧 accent 竖条）。编辑选中行 MAY 仅在行首冻结列（如勾选列）保留至多一条左侧 accent 指示，或仅通过略深背景区分；中间列与操作列 MUST NOT 各自出现独立的紫色竖线。若编辑选中曲与正在播放曲为同一行，则 MUST 仅展示播放态，不得叠加编辑态竖条或双重描边。

#### Scenario: 仅播放时可见播放行态

- **GIVEN** 管理员未点击任意行打开编辑
- **WHEN** 用户从更多菜单试听某曲且播放成功
- **THEN** 对应该曲的数据行展示「正在播放」行态
- **AND** 不错误复用「仅编辑选中」态作为播放反馈

#### Scenario: 编辑另一首时仍高亮正在播放

- **GIVEN** 歌曲 A 正在播放，用户点击歌曲 B 行打开编辑抽屉
- **WHEN** 列表仍显示 A 与 B 两行
- **THEN** A 行保持「正在播放」态
- **AND** B 行展示「编辑选中」较弱态（或等价可辨样式）

#### Scenario: 编辑选中行无每列竖条

- **GIVEN** 用户点击某行打开编辑且该行未在播放
- **WHEN** 用户横向浏览表格各列（含冻结列与中间列）
- **THEN** 任意两列之间不得因编辑选中而出现并列的多条紫色竖线
- **AND** 若存在左侧 accent，则整行至多一条且位于行首冻结列区域

#### Scenario: 后台播放行滚动可见且不受表头遮挡

- **GIVEN** 后台列表滚动容器为 `.adm-table-scroll` 且表头 sticky
- **WHEN** 正在播放行不在可视区内或部分被表头遮挡
- **THEN** 客户端滚动容器使该行完整出现在表头下方
- **AND** 滚动计算扣除 `thead` 高度（与前台方案 A 同意图）
