## ADDED Requirements

### Requirement: 后台歌曲管理页列表操作列仅更多下拉

后台歌曲管理页表格操作列（`.col-actions`）MUST 默认仅展示一个「更多」（⋮）触发按钮。编辑、播放（试听）、下载、删除 MUST 全部位于该按钮展开的下拉菜单（`.table-more-menu`）内，不得在行内并列展示独立的编辑/播放/下载快捷图标按钮。当曲目无浏览器可播音频时，菜单内播放项 MUST 为 disabled 并保留不可播原因提示（与现有 `songHasWebPlayableAudio` 语义一致）。删除 MUST 仍为菜单内危险操作项。

#### Scenario: 操作列仅显示更多按钮

- **GIVEN** 歌曲管理页列表已加载且存在至少一条歌曲
- **WHEN** 用户查看任意行的操作列
- **THEN** 可见的操作控件仅为「更多」（⋮）按钮
- **AND** 不存在独立的编辑、播放、下载行内图标按钮

#### Scenario: 从更多菜单编辑

- **GIVEN** 用户点击某行「更多」并展开菜单
- **WHEN** 用户点击菜单项「编辑」
- **THEN** 系统打开该曲右侧编辑抽屉
- **AND** 该行高亮为当前活动行（若现有行为存在）

#### Scenario: 从更多菜单播放

- **GIVEN** 某曲存在浏览器可播音频格式
- **WHEN** 用户从更多菜单选择「播放」或「试听」
- **THEN** 系统调用现有后台播放流程并开始播放
- **AND** 底部播放器展示当前曲名与播放状态

#### Scenario: 不可播曲目菜单播放禁用

- **GIVEN** 某曲无可浏览器播放的音频文件
- **WHEN** 用户展开该行的更多菜单
- **THEN** 播放/试听菜单项为 disabled
- **AND** 用户无法通过该菜单项触发播放

#### Scenario: 从更多菜单下载

- **GIVEN** 某曲存在可下载文件
- **WHEN** 用户从更多菜单选择「下载」
- **THEN** 系统触发与现有 `startDownloadFlow` 等价的下载流程

### Requirement: 后台歌曲管理页编辑抽屉影视剧字段

编辑歌曲右侧抽屉主表单 MUST 在可见区域提供「影视剧」文本输入字段，绑定歌曲 `film_tv` 属性。该字段 MUST NOT 仅存在于 `adm-hidden-filters` 或其他默认折叠隐藏区。保存元数据时 MUST 将输入值写入现有歌曲更新 API 的 `film_tv` 字段（空字符串视为清空）。

#### Scenario: 打开抽屉可见影视剧输入

- **GIVEN** 用户打开某首歌曲的编辑抽屉
- **WHEN** 抽屉元数据表单渲染完成
- **THEN** 用户在主表单可见区域看到标签为「影视剧」的输入框
- **AND** 无需展开隐藏筛选区即可编辑该字段

#### Scenario: 保存并回显影视剧

- **GIVEN** 用户在影视剧输入框填写「琅琊榜」并保存
- **WHEN** 用户再次打开该曲编辑抽屉
- **THEN** 影视剧输入框显示「琅琊榜」

### Requirement: 后台歌曲管理页编辑抽屉发行日期选择器

编辑抽屉中「发行日期」字段 MUST 使用日期选择器交互（如 HTML `input type="date"`），而非自由文本输入为主路径。表单与 API 之间 MUST 以 `YYYY-MM-DD` 格式字符串交换 `release_date`（与现有后端字段一致）。打开抽屉时 MUST 将歌曲已有 `release_date` 规范化为日期选择器可接受的值；无法解析的历史值 MAY 清空并允许用户重新选择。

#### Scenario: 发行日期以日期选择器展示

- **GIVEN** 用户打开编辑抽屉
- **WHEN** 用户查看发行日期字段
- **THEN** 该字段为日期选择器控件而非普通文本框
- **AND** 用户可通过日历/日期 UI 选择日期

#### Scenario: 保存发行日期

- **GIVEN** 用户在日期选择器中选择 2003-05-01
- **WHEN** 用户保存元数据
- **THEN** 请求体中 `release_date` 为 `2003-05-01`
- **WHEN** 用户再次打开该曲编辑抽屉
- **THEN** 日期选择器显示 2003-05-01

### Requirement: 后台歌曲管理页 Studio 风格底部播放器

后台歌曲管理页（`admin-page-music`）底部 MUST 提供与前台音乐库结构对齐的 Studio 风格播放器（`.studio-player`），包含：当前曲封面占位/缩略、曲名与艺人（或等价元数据）、播放/暂停、上一首、下一首、播放模式选择、可交互进度条与当前/总时长、音量控制。音频元素 MUST 隐藏原生 `controls`，由自定义 UI 驱动。播放器 MUST 接入现有后台播放队列与 `playSongInAdmin`（或等价）逻辑；播放、暂停、切歌、模式切换行为 MUST 与变更前后台播放能力一致或更强。歌曲列表主内容区 MUST 预留足够底部内边距，避免最后一行被固定播放器遮挡。

#### Scenario: 播放后播放器展示元数据

- **GIVEN** 用户从列表更多菜单或等效入口播放某曲
- **WHEN** 播放成功开始
- **THEN** 底部播放器显示该曲曲名
- **AND** 播放/暂停按钮反映正在播放状态
- **AND** 进度条随播放推进

#### Scenario: 播放暂停与切歌

- **GIVEN** 当前正在播放队列中某曲
- **WHEN** 用户点击播放器暂停按钮
- **THEN** 音频暂停且按钮变为播放态
- **WHEN** 用户点击下一首
- **THEN** 播放队列中下一可播曲目并开始播放（遵循当前播放模式）

#### Scenario: 音量与进度 seek

- **GIVEN** 播放器正在播放
- **WHEN** 用户拖动音量滑块
- **THEN** 音频音量相应变化
- **WHEN** 用户点击或拖动进度条
- **THEN** 播放位置跳转到对应时间点

#### Scenario: 列表不被播放器遮挡

- **GIVEN** 歌曲列表有多页数据且滚动至底部
- **WHEN** 用户查看最后一行
- **THEN** 最后一行完整可见且不被固定底部播放器覆盖
