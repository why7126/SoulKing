# 改动汇总（2026-03-26）

> 日期：**2026-03-26**。  
> 整理近期与「试听、入库、后台体验」相关的实现变更，便于回顾与发布说明。

---

## 1. FLAC 试听与播放接口（前后台）

### 问题

- 历史 `song_files` 行里 `is_playable_web` 可能仍为 `False`（早于「FLAC 标为可播」逻辑入库），导致 `GET /songs/{id}/play` 认为无可试听资源，管理端详情里 `file.is_playable_web` 也不展示试听。

### 后端

- **`app/services.py`**
  - `BROWSER_PLAYABLE_FORMATS`：与入库规则一致的浏览器可播扩展名集合（含 `flac`）。
  - `effective_is_playable_web(song_file)`：上述格式一律视为可播；否则回退数据库布尔字段。
- **`app/main.py`**
  - `get_song_play`：用 `effective_is_playable_web` 判断当前选中文件及可播回退列表。
  - `stream_content_type_for_song_file` + `GET /song-files/{id}/stream`：在 `mime_type` 缺失或为 `application/octet-stream` 时，对 FLAC 使用 `audio/flac`，减少浏览器拒播。
  - `song_file_to_out`：返回 `SongFileOut` 时写入**有效**的 `is_playable_web`（见下节一并说明）。

### 前端（同期）

- 后台 `admin.js`、前台 `frontend.js`、应用壳 `app.js` 中维护 `WEB_PLAYABLE_AUDIO_FORMATS`（含 `flac`），与后端策略对齐；APE 等不在集合内时不提供浏览器试听（见第 4 节）。

---

## 2. 保存元数据报 500（Internal Server Error）

### 原因

- `SongDetailOut` 含 `files: list[SongFileOut]`。若曾对 `SongFile` 直接 `SongFileOut.model_validate`，当库里存在 `format` 等必填列异常（如历史 NULL）时，**响应序列化阶段**触发 Pydantic 校验失败，表现为 **500**。

### 处理

- **`song_file_to_out`** 改为按字段**显式组装** `SongFileOut`，对空值做安全回退（如 `format` → `"unknown"`、`original_filename`、`file_size`、`created_at` 等），并仍用 `effective_is_playable_web` 写 `is_playable_web`。
- `GET/PUT /songs/{id}`、`PATCH/POST` 歌曲文件等凡返回 `SongFileOut` 的路径统一走 `song_file_to_out`。

---

## 3. 扫描目录 / 添加歌曲：不自动新建艺人

### 行为变更

- **`ingest_file`**（目录扫描 `scan_directory` 与后台「添加歌曲」`/admin/import-directory` 共用）不再调用 `get_or_create_artist`。
- 新增 **`lookup_artist_id_if_exists`**：仅当标签中的艺人名在 `artists` 表中已存在（忽略大小写）时设置 `artist_id` 并维持原有 `SongLeadArtist` 补全逻辑；否则**主艺人为空**，需在后台编辑中再关联或先在「艺人」里建档。
- **专辑**仍通过 `get_or_create_album` 按标签处理（未在本轮关闭自动建专辑）。

### 说明

- 向**已有歌曲**追加文件的 `attach_audio_file_to_song` 不涉及新建艺人，行为不变。
- 批量元数据等其它仍调用 `get_or_create_artist` 的路径未改（手工批量操作与扫描/导入区分）。

## 4. 同期相关改动（UI / 格式 / 部署）

以下与同一迭代周期内其它提交/会话一致，便于对照代码：

| 方向 | 内容 |
|------|------|
| 后台表格 | 元数据抽屉加宽、表单布局；歌曲表「操作」列使用 **`col-actions`** 做横向 sticky，避免误用 `:last-child`。 |
| 入库与扩展名 | 支持 **`.ape`** 扫描/添加；导入标题与存储路径规则与 **`source_filename`** 等约定一致（详见 `ingest_file` / `main` 导入）。 |
| APE 与 Docker | 不在镜像中安装 **ffmpeg**；浏览器端不对 APE 做转码试听。 |
| 前台列表 | 仅 APE 等不可 Web 播格式时，「试听 / 加入歌单」**禁用 + 提示**（`song-action-disabled-wrap` 等）。 |
| 前端缺陷修复 | `frontend.js` 中 `playSong` 曾出现重复 `const song` 导致脚本语法错误、整页无数据；已合并为单一变量。 |
