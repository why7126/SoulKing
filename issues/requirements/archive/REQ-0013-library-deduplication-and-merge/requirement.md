# 曲库去重与合并治理

## 背景
ProjectSoulKing 当前已在代码与已生效 OpenSpec 中实现 `library-deduplication-and-merge` 能力。为避免需求状态只存在于对话或规格结果中，本需求将该能力回填到 `issues/requirements`，作为可审计的历史需求档案。

## 目标用户
- 个人音乐库维护者
- 管理员
- 已登录普通用户（适用于面向前台或账号自助的能力）

## 用户价值
定义「曲库去重与合并」能力：在服务端按既定规则将多条曲目记录合并为一条「主曲目」，把重复曲目下的音频文件归属与关联数据迁到主曲目，并删除被合并掉的曲目记录；提供启动时一次性迁移、后台再次自动合并，以及后台按勾选指定主曲目的合并入口。本规范仅描述当前已实现行为；**入库/扫描阶段基于文件内容或哈希的重复跳过**属于另一条链路，不在此展开。

## Notes
- 自动合并返回的两个统计量：「重复组数量」计的是 **至少成功并入过一条从曲目** 的分组键个数；「从曲目并入条数」为成功并入的从曲目条数之和。同一组内若部分从曲目因时长差被跳过，组计数仍可能因其它从曲目成功而增加。
- 时长桶将非空毫秒时长按约 **两秒** 粒度四舍五入后映射；与时长容差 **五千毫秒** 共同约束自动合并中的配对。
- 启动迁移所用迁移标识为服务端源码中的固定字面字符串（便于对照实现）；规范正文不将该字面串固化为对外契约。
- 后台管理界面提供「合并重复曲目」与「勾选合并」操作入口；具体文案与按钮不属于本接口规范的强制范围。
- 请求体验证失败时的 HTTP 状态码与错误体形态由 Web 框架约定，本规范不逐项固化数字。

## Known Gaps
- **启动时合并失败**：自动合并流程内部未对合并失败做单独捕获；若合并抛出异常，可能导致整段启动时的结构就绪流程失败，具体表现依赖部署与全局异常处理。
- **后台再次自动合并失败**：手动触发接口未对合并逻辑单独包裹错误映射；失败时的响应形态依赖全局异常处理。
- **勾选合并后主曲缺失**：数据库合并提交后若按主曲标识再次查询不到主曲目（极端并发或数据异常），存储路径同步分支不会执行，但仍可能返回成功响应且仅含标识与计数；是否发生取决于运行时。
- **入库去重**：扫描或入库时基于文件内容/哈希的重复判定与跳过，与本文「曲目行合并」规则不同，不宜混读。
