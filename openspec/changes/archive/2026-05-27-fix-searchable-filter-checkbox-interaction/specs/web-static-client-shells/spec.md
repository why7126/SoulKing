## MODIFIED Requirements

### Requirement: 后台歌曲管理页快速筛选可搜索多选

后台壳内歌曲管理页的「更多筛选」面板 SHALL 为原唱、作词、作曲、标签、格式、语言、风格七个维度提供可搜索的多选下拉；用户 MUST 能通过关键字模糊匹配选项，并勾选或取消勾选多项；同一维度内多选为 OR，不同维度之间为 AND。原唱、作词、作曲、标签、语言、风格六个维度的可选项来源 SHALL 符合「后台歌曲管理页快速筛选选项来源」要求。筛选条件 MUST 通过曲库列表 API 查询参数提交并在服务端生效，而非仅在已加载的客户端数组上过滤。

多选下拉的选项行 MUST 使用与前台壳相同的 `searchable-select` 实现（共享脚本）：每一可见选项行的 checkbox MUST 在文档内具有唯一 `id`（不得仅依赖对 `option.value` 做 ASCII 清洗后的字符串）；用户点击该行 checkbox 或选项名称文案时，MUST 仅切换该行所对应 `<option>` 元素的 `selected` 状态，不得误操作同一下拉中其它选项（含中文名称、相同字符长度的多个选项）。

#### Scenario: 勾选后状态保持

- **GIVEN** 用户已打开「更多筛选」并展开某一维度的下拉
- **WHEN** 用户勾选或取消勾选某一选项
- **THEN** 该选项的勾选状态立即反映在 checkbox 上
- **AND** 关闭并再次打开下拉后勾选状态与之一致
- **AND** 触发器文案反映当前选中（未选时显示维度名称，选中一项时显示该项名称，选中多项时显示合并文案或计数）

#### Scenario: 搜索过滤选项

- **GIVEN** 某维度下拉已展开且存在多个可选项
- **WHEN** 用户在搜索框输入关键字
- **THEN** 仅显示标签或值与关键字模糊匹配的选项
- **AND** 对可见选项的勾选/取消勾选仍正确更新筛选结果

#### Scenario: 筛选结果更新

- **GIVEN** 用户已在至少一个维度选中一个或多个选项
- **WHEN** 选中集合发生变化
- **THEN** 客户端重新请求列表 API，歌曲列表仅显示满足各维度 OR/AND 规则的歌曲
- **AND** 「重置」按钮可见且可清空所有快速筛选与关键词

#### Scenario: 翻页不重建筛选项

- **GIVEN** 用户已在快速筛选中选中若干选项
- **WHEN** 用户切换列表页码或修改每页条数
- **THEN** 快速筛选的选中状态与触发器文案保持不变
- **AND** 下拉选项列表不因仅表格重绘而被清空或重置

#### Scenario: 曲库或参考数据变更后刷新选项

- **GIVEN** 曲库歌曲集合发生变更（如扫描完成、重新加载歌曲列表），和/或艺人、标签、语言管理数据发生变更
- **WHEN** 客户端完成相应数据刷新
- **THEN** 各维度下拉选项列表更新为与当前数据源一致的集合（艺人/标签/语言按管理列表，格式按曲库文件格式）
- **AND** 仍保留当前仍存在于新选项列表中的已选值

#### Scenario: 单选项维度可有效勾选

- **GIVEN** 某筛选维度在当前可选项中仅有一个选项
- **WHEN** 用户勾选该唯一选项
- **THEN** 该选项保持勾选状态
- **AND** 客户端重新请求列表且结果按该条件过滤
- **AND** 触发器显示该选项名称而非仅显示维度名称

#### Scenario: 中文选项名点击文案可勾选目标项

- **GIVEN** 语言或风格筛选下拉中存在至少两个中文名称选项（如「国语」「粤语」或「流行」「摇滚」）
- **WHEN** 用户点击第二项的选项名称文案（非第一项）
- **THEN** 仅第二项处于勾选状态
- **AND** 第一项保持未勾选（除非用户此前已勾选第一项）
- **AND** 列表请求携带的筛选参数对应第二项而非第一项

## ADDED Requirements

### Requirement: 可搜索多选筛选控件勾选交互

前台壳与后台壳中，由原生 `<select multiple>` 增强的「可搜索多选」筛选控件（`searchable-select`）SHALL 共用同一套客户端实现（单一模块或等价共享源码，不得在前台与后台维护两份 diverging 逻辑）。

对每一个动态生成的选项行：

- checkbox 元素的 `id` MUST 在整页文档内唯一，且在同一 `<select>` 内与选项一一对应；
- 生成 `id` 时 MUST NOT 仅使用对 `option.value` 剔除非 `[a-zA-Z0-9_-]` 字符后的结果作为唯一依据；
- 用户点击该行 checkbox 或该行选项展示文案时，MUST 仅切换该行绑定的 `<option>.selected`；
- 不得因重复 `id` 或错误的 `<label for>` 关联导致点击任意行都作用于第一项。

标签维度可使用数字 `tag.id` 作为 `value`；语言、风格、艺人名称等使用中文或任意 Unicode 字符串作为 `value` 时，交互要求相同。

#### Scenario: 前台语言筛选勾选非首项

- **GIVEN** 用户打开前台壳音乐库「更多筛选」并展开语言下拉，且存在「国语」「粤语」两个选项
- **WHEN** 用户点击「粤语」的文案区域
- **THEN** 「粤语」对应 checkbox 为勾选状态
- **AND** 「国语」未因该次点击而被勾选

#### Scenario: 前台风格筛选勾选非首项

- **GIVEN** 用户展开风格下拉，且存在「流行」「摇滚」
- **WHEN** 用户点击「摇滚」的文案区域
- **THEN** 仅「摇滚」被勾选
- **AND** 曲库列表请求包含「摇滚」映射的 `genre_ids`，而非「流行」

#### Scenario: 后台与前台行为一致

- **GIVEN** 同一筛选维度（如语言）在后台与前台均使用中文选项名
- **WHEN** 用户分别在后台歌曲管理页与前台音乐库执行「点击第二项文案以勾选」
- **THEN** 两处均仅第二项被勾选
- **AND** 两处触发器文案均反映第二项名称（或等价多选文案）

#### Scenario: 标签筛选仍为基准行为

- **GIVEN** 用户展开标签筛选且选项 value 为数字 id
- **WHEN** 用户勾选任意非第一项
- **THEN** 勾选行为正确且与修复前标签筛选可用时一致（无回归）
