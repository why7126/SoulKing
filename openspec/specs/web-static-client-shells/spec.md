# web-static-client-shells Specification

## Purpose

定义「Web 静态客户端壳」能力：服务端将静态资源目录以固定 URL 前缀对外提供；通过两条入口路径分别交付 **前台壳** 与 **后台壳** 的 HTML 文档；文档内挂载样式表与 **单一 ES 模块脚本入口**，由脚本调用后端接口并驱动界面（前台默认将站内路径拼为同源 URL）。本规范仅描述壳层交付与跨页导航；具体业务（曲库、歌单、扫描等）由其它能力规范覆盖。仓库中另有未接入任一脚本页的静态脚本文件，见 Known Gaps。
## Requirements
### Requirement: 静态资源 URL 前缀

服务端将应用静态资源目录挂载到固定 URL 前缀下，使浏览器可通过「前缀 + 相对路径」请求该目录内的样式表、脚本、图片及其它文件。

#### Scenario: 请求样式或脚本文件

- **GIVEN** 静态目录中存在某个样式或脚本文件
- **WHEN** 客户端请求该前缀加上对应文件路径
- **THEN** 服务端返回该文件内容（或常规缺失响应）

### Requirement: 前台入口路径

客户端访问站点根路径时，服务端返回 **前台壳** 的 HTML 文档（中文页面语言、含侧边栏与主内容区布局、引用站点徽标与全局样式等）。

#### Scenario: 打开根路径

- **GIVEN** 客户端请求站点根路径
- **WHEN** 服务端响应
- **THEN** 响应体为前台壳 HTML 文档

### Requirement: 后台入口路径

客户端访问管理入口路径时，服务端返回 **后台壳** 的 HTML 文档（中文页面语言、含侧边栏与主内容区布局、引用站点徽标与全局样式等）。

#### Scenario: 打开管理入口

- **GIVEN** 客户端请求管理入口路径
- **WHEN** 服务端响应
- **THEN** 响应体为后台壳 HTML 文档

### Requirement: 前台壳的样式与模块脚本

前台壳 HTML 引用全局样式表、前台增量样式表、外链字体（第三方字体服务），并以 **模块类型** 加载 **单一** 前台脚本文件；脚本 URL 可带查询参数用于缓存区分。

#### Scenario: 前台文档引用模块脚本

- **GIVEN** 前台壳 HTML 已加载
- **WHEN** 解析文档中的脚本引用
- **THEN** 存在且仅存在一条指向前台模块脚本的入口（模块类型）
- **AND** 同时存在指向全局样式表及前台增量样式表的链接

### Requirement: 后台壳的样式与模块脚本

后台壳 HTML 引用全局样式表、外链字体（第三方字体服务），并以 **模块类型** 加载 **单一** 后台脚本文件；脚本 URL 可带查询参数用于缓存区分。**不**引用前台增量样式表。

#### Scenario: 后台文档引用模块脚本

- **GIVEN** 后台壳 HTML 已加载
- **WHEN** 解析文档中的脚本引用
- **THEN** 存在且仅存在一条指向后台模块脚本的入口（模块类型）
- **AND** 存在指向全局样式表的链接
- **AND** 不出现指向前台增量样式表的链接

### Requirement: 前台 API 请求的 URL 组装

前台模块脚本通过封装函数发起数据请求：若传入路径已为完整的 `http` 或 `https` 链接，则按该链接访问（可能与页面 **不同源**）；否则将浏览器当前来源与以斜杠开头的路径拼接为绝对 URL，使请求与页面 **同源**。

#### Scenario: 常规接口路径转为同源 URL

- **GIVEN** 用户已打开前台壳页面且脚本运行中
- **WHEN** 封装函数收到以斜杠开头的接口路径（非完整 http(s) 链接）
- **THEN** 实际请求目标的主机与端口与当前页面一致（同源）

### Requirement: 后台数据请求的 fetch 路径形态

后台模块脚本的通用请求封装将路径字符串交给浏览器发起网络请求；壳内现有调用均使用以斜杠开头的站点根相对路径（或等价完整路径片段），从而在同一站点来源下访问接口。个别批量下载流程另行发起网络请求，仍使用站点根下的路径。

#### Scenario: 典型列表与表单请求使用根相对路径

- **GIVEN** 用户已打开后台壳页面且脚本运行中
- **WHEN** 通用封装使用以斜杠开头的路径发起数据请求
- **THEN** 请求解析为当前站点来源下的对应资源路径

### Requirement: 壳内前后台跳转

前台壳提供前往管理入口的控件；后台壳提供返回站点根路径的控件。用户激活后，浏览器 **整页导航** 至对应路径（地址栏变为管理入口路径或根路径）。

#### Scenario: 从前台进入后台

- **GIVEN** 用户在前台壳页面
- **WHEN** 用户激活「进入后台」类控件
- **THEN** 浏览器导航至管理入口路径

#### Scenario: 从后台返回前台

- **GIVEN** 用户在后台壳页面
- **WHEN** 用户激活「返回前台」类控件
- **THEN** 浏览器导航至站点根路径

### Requirement: 后台歌曲管理页快速筛选选项来源

后台壳内歌曲管理页「更多筛选」中，原唱、作词、作曲、标签、语言、风格六个维度的下拉可选项 MUST 取自参考数据管理列表，而非从当前曲库歌曲字段推导；格式维度不受本要求约束。

各维度选项来源 SHALL 为：

| 维度 | 数据来源 | 过滤规则 |
|------|----------|----------|
| 原唱 | 艺人管理（`/people`） | `types` 包含「歌手」 |
| 作词 | 艺人管理 | `types` 包含「作词」 |
| 作曲 | 艺人管理 | `types` 包含「作曲」 |
| 标签 | 标签管理（`/tags`） | 全部标签名称 |
| 语言 | 语言管理（`/languages`） | 全部语言名称 |
| 风格 | 风格管理（`/genres`） | 全部风格名称 |

选项值 SHALL 为对应条目的 **名称** 字符串（与列表过滤时使用的歌曲元数据字段一致），并按名称升序排列。

风格筛选在 UI 上 MUST 位于语言筛选之后。用户选择风格后，客户端 MUST 将所选名称映射为 `genre_ids` 并随 `GET /songs` 提交；同维度多选为 OR，跨维度 AND。

#### Scenario: 原唱选项来自歌手类型艺人

- **GIVEN** 艺人管理中存在名称「甲」且 `types` 包含「歌手」，存在名称「乙」且 `types` 仅包含「作词」
- **WHEN** 用户打开歌曲管理页「更多筛选」中的原唱下拉
- **THEN** 可选项包含「甲」
- **AND** 可选项不包含「乙」

#### Scenario: 作词与作曲选项按类型区分

- **GIVEN** 艺人「丙」的 `types` 为「作词」，艺人「丁」的 `types` 为「作曲」
- **WHEN** 用户分别打开作词、作曲筛选下拉
- **THEN** 作词可选项包含「丙」且不包含「丁」（除非「丁」亦为作词类型）
- **AND** 作曲可选项包含「丁」且不包含「丙」（除非「丙」亦为作曲类型）

#### Scenario: 标签、语言与风格选项来自管理列表

- **GIVEN** 标签管理中存在「流行」，语言管理中存在「国语」，风格管理中存在「摇滚」，且当前曲库中没有任何歌曲带有该标签、语言或风格
- **WHEN** 用户打开标签、语言或风格筛选下拉
- **THEN** 可选项仍分别包含「流行」「国语」「摇滚」

#### Scenario: 风格筛选位于语言之后

- **GIVEN** 用户展开歌曲管理页「更多筛选」面板
- **WHEN** 用户从左至右查看筛选控件顺序
- **THEN** 「风格」控件紧跟在「语言」控件之后

#### Scenario: 参考数据变更后刷新筛选项

- **GIVEN** 用户已在歌曲管理页
- **WHEN** 客户端完成艺人、标签、语言或风格管理数据的重新加载（如新增、编辑、删除后触发的 `loadPeople` / `loadTags` / `loadLanguages` / `loadGenres`）
- **THEN** 对应维度的下拉选项列表更新为与管理数据一致的集合
- **AND** 仍保留当前仍存在于新选项列表中的已选值

### Requirement: 后台歌曲管理页列表表格列与顺序

后台壳内歌曲管理页主表格 SHALL 按下列顺序展示列（不含行首勾选列）：歌曲、原唱、作词、作曲、专辑、语言、风格、影视剧、标签、格式、时长、发行日期、元数据、创建时间、更新时间、操作。

各列展示规则 SHALL 为：

| 列 | 数据来源 / 展示 |
|----|-----------------|
| 歌曲 | 歌曲标题；无副文案时长（时长独立列） |
| 原唱 | `lead_artist` 或等价主唱展示串 |
| 作词 | 词作者名字列表，以「、」或「 / 」连接 |
| 作曲 | 曲作者名字列表，以「、」或「 / 」连接 |
| 专辑 | 专辑名 |
| 语言 | 语言展示名 |
| 风格 | `genre` 展示名；无值时显示「—」 |
| 影视剧 | `film_tv` 文本；无值时显示「—」 |
| 标签 | 标签名列表 |
| 格式 | 代表性音频格式标签 |
| 时长 | `duration_ms` 格式化为 `mm:ss` |
| 发行日期 | `release_date` 原文或格式化展示 |
| 元数据 | 元数据完成度进度条与百分比 |
| 创建时间 | `created_at` 本地化展示 |
| 更新时间 | `updated_at` 本地化展示 |
| 操作 | 见「后台歌曲管理页列表操作按钮」 |

表格 MUST NOT 包含「年份」「封面」「状态」「歌词」列。

支持排序的列（若实现表头排序）SHALL 与上述字段对应，且排序请求参数与曲库列表 API 的 `sort_by` 一致；「影视剧」列排序参数 MUST 为 `film_tv`；「风格」列排序参数 MUST 为 `genre`。

#### Scenario: 列顺序与必填字段展示

- **GIVEN** 歌曲管理页已加载且列表至少一条记录
- **WHEN** 用户查看表头
- **THEN** 表头从左至右（勾选列之后）依次为歌曲、原唱、作词、作曲、专辑、语言、风格、影视剧、标签、格式、时长、发行日期、元数据、创建时间、更新时间、操作
- **AND** 不出现年份、封面、状态、歌词列

#### Scenario: 空字段占位

- **GIVEN** 某歌曲缺少作词或作曲关联，或 `film_tv` 为空，或 `genre` 为空
- **WHEN** 渲染该行
- **THEN** 对应单元格显示「—」或等价占位

#### Scenario: 影视剧列展示与排序

- **GIVEN** 某歌曲 API 响应 `film_tv` 为「琅琊榜」
- **WHEN** 该歌曲出现在后台列表中
- **THEN** 影视剧列单元格展示「琅琊榜」
- **WHEN** 用户点击影视剧列表头排序
- **THEN** 列表请求携带 `sort_by=film_tv` 及当前升降序参数

#### Scenario: 风格列展示与排序

- **GIVEN** 某歌曲 API 响应 `genre` 为「流行」
- **WHEN** 该歌曲出现在后台列表中
- **THEN** 风格列单元格展示「流行」
- **WHEN** 用户点击风格列表头排序
- **THEN** 列表请求携带 `sort_by=genre` 及当前升降序参数

### Requirement: 后台歌曲管理页主区滚动与视口

后台歌曲管理页在标准桌面视口下，浏览器窗口 MUST NOT 因歌曲列表区域而出现整页（`body` 或主内容 wrap）纵向滚动条。列表数据行的纵向滚动 MUST 仅发生在表格容器（如 `.adm-table-scroll`）内部；列表数据列的横向滚动 MUST 仅发生在同一表格容器内部。表底分页栏 MUST 位于表格容器下方、在同一主列布局内，且在不滚动页面的情况下始终可见。

#### Scenario: 视口内无页面级纵滚

- **GIVEN** 用户打开歌曲管理页且曲库有数据
- **WHEN** 用户查看浏览器窗口右侧滚动条
- **THEN** 页面级（body 或 `.app-admin-main-wrap`）不出现用于浏览歌曲列表的纵向滚动条
- **AND** 表格区域内部可纵向滚动以查看更多行

#### Scenario: 视口内无页面级横滚

- **GIVEN** 用户打开歌曲管理页且表格列总宽度大于视口宽度
- **WHEN** 用户查看浏览器窗口底部滚动条
- **THEN** 页面级（body 或 `.app-admin-main-wrap`）不出现用于浏览歌曲列表列内容的横向滚动条
- **AND** 表格区域内部可横向滚动以访问全部列

#### Scenario: 表底分页栏固定在列表区底部

- **GIVEN** 歌曲列表已加载且 `total` 大于 0
- **WHEN** 用户未滚动页面
- **THEN** 表底分页栏（含总数文案与翻页控件）出现在当前视口内列表区域底部

### Requirement: 后台歌曲管理页列表容器双轴滚动

歌曲管理页表格数据（表头与 tbody 行）的纵向与横向滚动 MUST 仅发生在列表滚动容器（如 `.adm-table-scroll`）内部。当表格内容高度超出容器可视高度时，容器 MUST 出现纵向滚动条并可滚动浏览当前页全部行；当表格列总宽度超出容器可视宽度时，容器 MUST 出现横向滚动条并可滚动浏览全部数据列（含发行日期、元数据、创建时间、更新时间等中间列）。表底分页栏 MUST 位于滚动容器之外、列表区底部，且不随表格内容滚动。

纵向滚动时，表头（`thead`）SHALL 在滚动容器顶部保持可见（sticky），以便用户对照列名。

#### Scenario: 纵向滚动浏览当前页全部行

- **GIVEN** 歌曲管理页已加载且当前页行数超出列表容器可视高度
- **WHEN** 用户在列表滚动容器内向下滚动
- **THEN** 容器出现纵向滚动条（或等价可滚动指示）
- **AND** 用户可滚动至当前页最后一行
- **AND** 表头在滚动过程中保持固定在容器顶部可见
- **AND** 表底分页栏位置不变且仍可见

#### Scenario: 横向滚动浏览全部数据列

- **GIVEN** 歌曲管理页已加载且表格列总宽度大于列表容器宽度
- **WHEN** 用户在列表滚动容器内横向滚动
- **THEN** 容器出现横向滚动条（或等价可滚动指示）
- **AND** 用户可滚动访问中间列（如发行日期、元数据、创建时间、更新时间）
- **AND** 页面级（body 或 `.app-admin-main-wrap`）不出现用于浏览表格列的横向滚动条

#### Scenario: 滚动容器边界不受 display contents 破坏

- **GIVEN** 用户打开歌曲管理页
- **WHEN** 检查列表 DOM 结构
- **THEN** 表格包裹于具备 `overflow: auto`（或等价双轴滚动）的独立容器内
- **AND** 该容器参与 flex 列布局并具备 `min-height: 0`（或等价高度约束），使滚动发生在容器内而非整页

### Requirement: 后台歌曲管理页列表操作按钮

操作列 SHALL 提供编辑、播放、下载三类主操作：编辑打开编辑抽屉；播放仅在存在可浏览器试听的音频时可用；下载打开格式选择或直链下载流程（与现有单曲下载行为一致）。删除等破坏性操作 MAY 保留在「更多」菜单中。

操作列在用户横向滚动表格时 MUST 对**表头与每一数据行**均采用右侧冻结（`position: sticky; right: 0` 或等价实现），使主操作按钮始终贴在列表滚动容器右缘且可点击。操作列单元格 MUST 保持表格单元格显示类型（不得对 `<td class="col-actions">` 使用 `display: flex` 或 `display: block` 等破坏 `table-cell` 的样式）；按钮组的 flex 布局 SHALL 应用于单元格内层包裹元素。列宽 MUST 足以同时展示编辑、播放、下载、更多四个主控件，避免裁切或重叠不可点。

#### Scenario: 可播放歌曲显示播放

- **GIVEN** 列表行对应歌曲存在可 Web 试听的音频变体
- **WHEN** 用户查看操作列
- **THEN** 播放操作可用
- **AND** 激活后发起试听（与现有 `play` 流程一致）

#### Scenario: 不可播放时禁用或隐藏播放

- **GIVEN** 列表行对应歌曲无可 Web 试听变体
- **WHEN** 用户查看操作列
- **THEN** 播放操作不可用或不出现在主操作区

#### Scenario: 横向滚动后仍可见操作与更新时间

- **GIVEN** 表格列总宽度大于表格容器宽度
- **WHEN** 用户将表格横向滚动到最右（或操作列已冻结在右侧）
- **THEN** 用户能看到「更新时间」列内容
- **AND** 用户能看到并点击操作列中的编辑、下载等主操作按钮

#### Scenario: 横向滚动中间位置时各行操作按钮仍冻结

- **GIVEN** 表格列总宽度大于列表滚动容器宽度，且用户已将横向滚动条置于中间位置（既未滚到最左也未滚到最右，中间列如「发行日期」可见）
- **WHEN** 用户查看任意可见数据行的操作列
- **THEN** 该行编辑、播放、下载、更多按钮仍出现在滚动容器右缘的操作列区域内
- **AND** 与表头「操作」列横向对齐
- **AND** 用户可点击其中任一主操作按钮

### Requirement: 后台歌曲管理页表格冻结列

当歌曲管理页表格列总宽度超出列表滚动容器可视宽度时，用户横向滚动表格时**勾选**列与**歌曲**列 MUST 保持固定可见（sticky left），**操作**列 MUST 保持固定可见（sticky right）；表头与每一数据行同步冻结，中间列（原唱至更新时间）随横向滚动移动。

表格 MUST 使用 `border-collapse: separate`（或等价实现）以保证 sticky 列 z-index 在横向滚动时生效。冻结列单元格 MUST 使用不透明背景色覆盖其下方滚动列内容；横向滚动至任意位置时，滚动列的文字或控件 MUST NOT 与冻结列内容发生视觉重叠或「透出」。

操作列在用户横向滚动时 MUST 对表头与每一数据行均采用右侧冻结，使编辑、播放、下载、更多等主操作按钮始终贴在列表滚动容器右缘且可点击。操作列单元格 MUST 保持表格单元格显示类型；按钮组 flex 布局 SHALL 应用于单元格内层包裹元素（与「后台歌曲管理页列表操作按钮」一致）。

#### Scenario: 横向滚动时勾选与歌曲列固定

- **GIVEN** 用户处于歌曲管理页且表格需横向滚动

### Requirement: 后台歌曲管理页服务端分页与总数展示

歌曲管理页列表数据 MUST 通过曲库列表 API 的 `offset` 与 `limit` 分页获取，不得依赖一次性拉取固定上限（如 500）后在客户端切片作为唯一分页来源。页脚分页控件切换页码或每页条数时 MUST 重新请求当前页数据。

表底栏 SHALL 为单行布局：**左侧**展示当前筛选条件下的总数文案（如「共 N 首」或「共 N 首（已筛选）」）；**右侧**展示翻页控件（上一页、页码、下一页、每页条数）。表底 MUST NOT 包含批量编辑、批量标签、批量删除等批量操作按钮或「未选择项目」类表底批量区（批量操作保留在页面顶部工具栏）。

页面顶部「音乐总数」统计卡片 SHALL 展示全库歌曲条数（`library_total`），与是否应用筛选无关。

快速筛选、关键词、排序变更时 MUST 将页码重置为第 1 页并重新请求列表。

### Requirement: 后台歌曲管理页快速筛选可搜索多选

后台壳内歌曲管理页的「更多筛选」面板 SHALL 为原唱、作词、作曲、标签、格式、语言、风格七个维度提供可搜索的多选下拉；用户 MUST 能通过关键字模糊匹配选项，并勾选或取消勾选多项；同一维度内多选为 OR，不同维度之间为 AND。原唱、作词、作曲、标签、语言、风格六个维度的可选项来源 SHALL 符合「后台歌曲管理页快速筛选选项来源」要求。筛选条件 MUST 通过曲库列表 API 查询参数提交并在服务端生效，而非仅在已加载的客户端数组上过滤。

### Requirement: 可搜索多选筛选控件勾选交互

前台壳与后台壳中，由原生 `<select multiple>` 增强的「可搜索多选」筛选控件（`searchable-select`）SHALL 共用同一套客户端实现（单一模块或等价共享源码，不得在前台与后台维护两份 diverging 逻辑）。

对每一个动态生成的选项行：

- checkbox 元素的 `id` MUST 在整页文档内唯一，且在同一 `<select>` 内与选项一一对应；
- 生成 `id` 时 MUST NOT 仅使用对 `option.value` 剔除非 `[a-zA-Z0-9_-]` 字符后的结果作为唯一依据；
- 用户点击该行 checkbox 或该行选项展示文案时，MUST 仅切换该行绑定的 `<option>.selected`；
- 不得因重复 `id` 或错误的 `<label for>` 关联导致点击任意行都作用于第一项。

标签维度可使用数字 `tag.id` 作为 `value`；语言、风格、艺人名称等使用中文或任意 Unicode 字符串作为 `value` 时，交互要求相同。

### Requirement: 前台壳侧栏收起与展开

前台壳左侧主导航栏 SHALL 提供可见的折叠切换控件（图标按钮）。用户激活该控件时 SHALL 在 **展开** 与 **收起** 两种宽度之间切换：展开态保持现有完整侧栏（品牌文案、导航图标与文字、曲库统计、底部用户区）；收起态 SHALL 缩为仅图标窄栏（隐藏品牌与导航文字、曲库统计与用户名，保留导航图标与底部头像按钮）。

收起/展开切换 MUST 使主内容区宽度随之调整。前台底部播放条等依赖侧栏宽度的固定层 MUST 与侧栏同步过渡。

前台壳 MUST 将用户最后一次收起/展开偏好持久化至浏览器 `localStorage`（键名实现自定但前后台 MUST 分离）；用户再次打开前台壳时 SHALL 恢复该偏好。折叠切换控件 MUST 提供可访问名称（如 `aria-label`）及 `aria-expanded` 反映当前是否展开。

- **THEN** 侧栏宽度缩小为仅图标窄栏
- **AND** 导航项文字与品牌标题不可见
- **AND** 导航图标仍可见且可点击

### Requirement: 后台壳侧栏收起与展开

后台壳左侧主导航栏 SHALL 提供与前台壳一致的折叠切换交互：图标按钮切换展开/收起；收起态为仅图标窄栏，展开态保持现有完整侧栏（品牌、导航、底部用户区）。

后台壳 MUST 独立持久化收起/展开偏好至 `localStorage`（与前台键名分离）；用户再次打开后台壳时 SHALL 恢复该偏好。切换控件 MUST 提供 `aria-label` 与 `aria-expanded`。

#### Scenario: 点击图标展开后台侧栏

### Requirement: 前台壳底部播放器紧凑两行布局

前台壳底部固定播放器（`.studio-player`）SHALL 采用 **两行** 纵向结构，且整个播放器占用高度 MUST 明显低于改版前三列 + 中列纵向堆叠的实现。

- **第一行（控制行）** SHALL 容纳现有播放器能力：曲目封面与曲名/艺人展示、上一首/播放暂停/下一首、播放模式下拉、播放进度条与当前/总时长、音量控制，以及既有右侧辅助按钮（播放当前列表、词、全屏等，若页面中仍存在）。
- **第二行（歌词行）** SHALL **仅** 展示歌词同步/占位文案（`#playerLyricLine`），横跨播放器主内容宽度；MUST NOT 将歌词与控制按钮、进度条置于同一行。

控制行内控件 SHOULD 以单行横向排列为主；允许在窄视口下控制行 **内部** 换行，但 MUST NOT 将 transport、进度条、歌词拆成三行纵向堆叠（即不得复现「transport 一行 + 进度一行 + 歌词一行」均在控制区内的布局）。

播放器 `position: fixed` 与 `left` 随侧栏展开/收起同步过渡的行为 MUST 保持不变。

主内容滚动区域（含音乐库列表）SHALL 预留底部内边距（或等效布局），其值 MUST 不小于压缩后播放器实际高度，确保列表最后一行不被播放器遮挡。

- **GIVEN** 用户打开前台壳并查看底部播放器
- **WHEN** 用户观察播放器垂直结构
- **THEN** 可见区域由上至下仅为控制行与歌词行共两行
- **AND** 歌词文案出现在控制行下方独立一行

#### Scenario: 控制行包含既有播放能力

- **GIVEN** 用户正在播放一首可试听曲目
- **WHEN** 用户查看控制行
- **THEN** 可见播放/暂停、上一首、下一首与播放模式下拉
- **AND** 可见进度条与当前时间、总时长
- **AND** 可见音量滑块与曲名/艺人信息

#### Scenario: 歌词行独占第二行

- **GIVEN** 用户正在播放曲目
- **WHEN** 用户查看 `#playerLyricLine` 所在区域
- **THEN** 该行位于控制行之下
- **AND** 该行不包含 transport 按钮或进度条元素

#### Scenario: 列表末行不被播放器遮挡

- **GIVEN** 用户处于音乐库视图且列表可纵向滚动
- **WHEN** 用户滚动至列表最后一行
- **THEN** 最后一行完整可见于播放器上缘之上
- **AND** 不被固定底栏遮挡

#### Scenario: 侧栏收起时播放器宽度同步

- **GIVEN** 用户通过侧栏折叠控件收起左侧导航
- **WHEN** 过渡动画结束
- **THEN** 底部播放器 `left` 与主内容区对齐窄侧栏
- **AND** 两行布局仍保持控制行在上、歌词行在下

### Requirement: 前台播放器 LRC 同步显示

当前台壳正在播放可试听曲目且该曲存在可读取的歌词时，`#playerLyricLine` SHALL 随音频播放进度更新为当前时间对应的歌词行文本。切换播放曲目时，客户端 MUST 重新加载该曲歌词；加载完成前可显示加载中或保留上一曲文案直至更新。

若无歌词或歌词接口返回无歌词，则 `#playerLyricLine` SHALL 显示固定占位文案（如「当前暂无歌词同步显示」）。若有歌词但当前时间点无匹配行，SHALL 显示空行、省略号或上一行文本之一，行为须在实现中一致。

更新歌词 DOM 时 SHOULD 仅在当前行文本变化时写入，以避免不必要的重绘。

#### Scenario: 有 LRC 时随播放进度更新

- **WHEN** 播放进度越过某一歌词行的时间戳
- **THEN** `#playerLyricLine` 显示该行文本

#### Scenario: 切歌后歌词更新

### Requirement: 前台播放器歌词行显示切换

前台壳底部播放器控制行中的「词」按钮（`#playerLyricsToggleBtn` 或等效稳定选择器）SHALL 切换第二行歌词区域（`.studio-player-row--lyrics`）的显示与隐藏。

- 默认状态 SHALL 为 **显示** 歌词行（与改版前行为一致）。
- 隐藏歌词行时，播放器总高度 MUST 收缩为仅控制行高度；主内容滚动区域的底部留白 MUST 同步减小，确保列表末行不被遮挡。
- 按钮 MUST 暴露可访问性状态：`aria-pressed` 在显示时为 `true`，隐藏时为 `false`；SHOULD 在激活态有视觉区分（如 `.is-active`）。
- 用户的显示/隐藏偏好 SHOULD 持久化于 `localStorage`（键名由实现固定），刷新页面后恢复上次选择。
- 隐藏歌词行时，客户端 MAY 继续加载与维护 LRC 同步状态；再次显示时 SHOULD 立即呈现当前行文本，无需重新请求。

- **THEN** `.studio-player-row--lyrics` 不可见
- **AND** 播放器占用高度小于显示歌词行时的高度
- **AND** 「词」按钮 `aria-pressed` 为 `false`

#### Scenario: 再次点击显示歌词行

- **GIVEN** 歌词行已被隐藏
- **WHEN** 用户再次点击「词」按钮
- **THEN** `.studio-player-row--lyrics` 可见
- **AND** `#playerLyricLine` 显示当前曲目歌词或占位文案
- **AND** 「词」按钮 `aria-pressed` 为 `true`

#### Scenario: 刷新后恢复偏好

- **GIVEN** 用户曾将歌词行设为隐藏且偏好已写入 `localStorage`
- **WHEN** 用户刷新页面并再次打开前台壳
- **THEN** 歌词行初始为隐藏状态
- **AND** 主内容区底部留白与隐藏态播放器高度一致

#### Scenario: 隐藏态下列表末行可见

- **GIVEN** 歌词行处于隐藏状态且用户处于音乐库列表视图
- **WHEN** 用户滚动至列表最后一行
- **THEN** 最后一行完整可见于播放器上缘之上

Tab 切换 MUST 更新 `inspectorTab` 状态并渲染对应面板内容，不得仅切换按钮高亮而无内容变化。

#### Scenario: 选中曲目后查看歌词 Tab

- **WHEN** 用户点击检查器「歌词」Tab

#### Scenario: 无歌词时的 Tab 提示

- **WHEN** 用户打开「歌词」Tab
- **THEN** 面板显示无歌词说明，而非空白无提示

### Requirement: 后台编辑抽屉歌词上传

后台壳歌曲编辑抽屉中的「替换歌词」控件 SHALL 触发文件选择（接受 `.lrc`），并通过歌曲歌词上传接口提交；成功后更新 `#editLyricName` 等展示为当前文件名。失败时 SHALL 以 Toast 或等价方式显示错误，不得仅显示「即将推出」类占位。

#### Scenario: 替换歌词成功

- **WHEN** 用户选择有效 `.lrc` 并确认上传

### Requirement: 后台歌曲管理页编辑抽屉宽度

后台壳内歌曲管理页右侧编辑面板（`#adminEditPanel` / `.admin-edit-panel`）在打开状态（`.is-open`）时，宽度 MUST 大于变更前默认值（`380px`），并通过 CSS 变量（如 `--adm-edit-w`）统一配置，以便容纳原唱/作词/作曲多选控件与标签多选下拉。窄屏下宽度 MUST 不超过视口宽度。

- **THEN** 面板宽度不小于 `460px`（或由 `--adm-edit-w` 设定的等价值）
- **AND** 原唱、作词、作曲三个多选触发器可在同一行或相邻行内完整显示而不严重重叠

### Requirement: 后台歌曲管理页编辑抽屉原唱作词作曲字段

编辑抽屉主表单 MUST 提供 **原唱**、**作词**、**作曲** 三个独立字段（不得使用单一「艺人」标签合并原唱）。三个字段 MUST 使用与编辑抽屉「语言」字段相同的多选交互组件（`multi-select`）：支持关键字模糊搜索选项、多选勾选/取消、在搜索框输入无完全匹配项时创建并选中、触发器以 chip 展示已选项。原唱对应艺人类型「歌手」；作词、作曲对应艺人类型「作词」「作曲」。作词、作曲字段 MUST 位于主表单可见区域，不得仅存在于 `adm-hidden-filters` 隐藏区。

#### Scenario: 打开编辑抽屉显示三个艺人字段

- **WHEN** 用户输入不存在的艺人名并选择「创建并添加」

#### Scenario: 保存后作词作曲回显

- **WHEN** 用户再次打开该曲编辑抽屉
- **THEN** 作词、作曲多选触发器分别展示 A、B（或等价 chip）

### Requirement: 后台歌曲管理页编辑抽屉标签多选

编辑抽屉中的「标签」字段 MUST 使用与「语言」字段相同的多选交互（`multi-select`），取代平铺 checkbox 列表。行为 MUST 包括：从标签管理列表（`/tags`）加载选项、关键字模糊搜索、多选、搜索框内输入新建标签（`POST /tags`）并自动选中。保存元数据时 MUST 提交所选 `tag_ids`（或与现有保存 API 等价的标签 id 列表）。

#### Scenario: 新建标签并选中

- **WHEN** 用户在标签搜索框输入「Demo」并确认创建
- **THEN** 「Demo」出现在标签管理数据中
- **AND** 该标签处于当前歌曲已选标签集合中

### Requirement: 后台歌曲管理页编辑抽屉风格字段

编辑抽屉主表单 MUST 在可见区域提供「风格」字段，交互 MUST 与「语言」字段一致：使用 `multi-select` 组件，支持从风格管理列表（`/genres`）加载选项、关键字模糊搜索、多选勾选/取消、搜索框内输入无完全匹配项时创建风格（`POST /genres`）并自动选中、触发器以 chip 展示已选项。该字段 MUST NOT 仅存在于 `adm-hidden-filters` 或其它默认隐藏区。字段在表单中的位置 MUST 紧邻「语言」字段（同一网格行或相邻表单项，语言在前、风格在后）。保存元数据时 MUST 提交所选 `genre_ids`（或与现有保存 API 等价的风格 id 列表）。

#### Scenario: 打开编辑抽屉可见风格字段

- **GIVEN** 用户打开某首歌曲的编辑抽屉
- **WHEN** 抽屉元数据表单渲染完成
- **THEN** 用户可在主表单可见区域看到标签为「风格」的多选控件
- **AND** 该控件与「语言」多选控件均不在 `adm-hidden-filters` 内

#### Scenario: 风格模糊搜索与新建

- **GIVEN** 编辑抽屉已打开且风格管理中存在名称包含「流」的风格
- **WHEN** 用户在风格多选搜索框输入「流」
- **THEN** 下拉列表显示名称模糊匹配的风格选项
- **WHEN** 用户输入不存在的风格名并选择创建
- **THEN** 系统创建该风格并加入当前歌曲已选风格集合

#### Scenario: 保存后风格回显

- **GIVEN** 用户为某曲选择了风格「流行」并保存
- **WHEN** 用户再次打开该曲编辑抽屉
- **THEN** 风格多选触发器展示「流行」（或等价 chip）

### Requirement: 后台歌曲管理页编辑抽屉格式只读聚合

编辑抽屉 MUST NOT 提供用户可编辑的「格式」表单控件（无 text input、select 等用于修改格式的字段）。该曲关联的 **全部** 音频文件（`detail.files` 或等价结构）的 `format` MUST 自动聚合为只读展示（如 `MP3 / FLAC`），去重后以大写扩展名形式呈现；当无任何音频文件时展示占位（如「—」）。添加、删除或替换音频文件后，只读格式展示 MUST 同步更新，且无需用户保存元数据即可反映文件列表变化。

#### Scenario: 多格式音频只读展示

- **GIVEN** 某曲关联 `song.mp3`（format mp3）与 `song.flac`（format flac）
- **WHEN** 用户打开编辑抽屉
- **THEN** 抽屉内可见只读格式信息包含 MP3 与 FLAC（顺序不限，须去重）

- **WHEN** 用户通过「添加文件」成功上传 FLAC
- **THEN** 只读格式展示更新为包含 MP3 与 FLAC

- **THEN** 只读格式展示为占位符或空状态文案
- **AND** 用户无法通过格式字段输入修改格式

### Requirement: 后台歌曲管理页编辑抽屉多选选项列表对齐

编辑抽屉内原唱、作词、作曲、语言、标签等字段使用的 `multi-select` 下拉菜单中，选项行（含 checkbox 与名称文案）MUST 保持整齐对齐：checkbox MUST 为固定小尺寸控件，不得被编辑抽屉内针对文本输入框的样式（如 `width: 100%`、大 padding、边框背景）拉伸或挤占整行。提示行（`multi-select-meta-hint`）、新建行（`multi-select-meta-row`）与勾选项行（`artist-option`）的左内边距 MUST 视觉一致。在 `.adm-form-grid-3` 等窄列布局中，下拉菜单 MUST 保持可读（如设置合理 `min-width` 或允许菜单相对触发器向右展开），不得因列宽约 150px 导致选项严重错位不可读。

#### Scenario: 选项行 checkbox 与名称同一行左对齐

- **GIVEN** 用户打开编辑抽屉并展开任一元数据多选（如原唱、标签）
- **WHEN** 下拉列表展示若干可勾选项
- **THEN** 每行 checkbox 宽度约为标准复选框尺寸（约 16px），不与行宽同宽
- **AND** 名称文案紧邻 checkbox 右侧同一行显示
- **AND** 各行 checkbox 左缘垂直对齐

#### Scenario: 三列艺人字段下拉可读

- **GIVEN** 编辑抽屉处于打开状态且原唱、作词、作曲位于三列网格中
- **WHEN** 用户展开任一职艺人多选下拉
- **THEN** 下拉菜单宽度不小于 200px（或等价 min-width）
- **AND** 选项列表不出现 checkbox 被拉满整行导致文字不可读的情况

#### Scenario: 搜索框仍保持全宽

- **GIVEN** 用户展开语言或标签多选下拉
- **WHEN** 用户查看搜索输入框
- **THEN** 搜索框仍占满菜单内容区宽度
- **AND** 搜索框样式与抽屉内其它文本输入框一致（非 checkbox）

### Requirement: 后台歌曲管理页列表操作列仅更多下拉

后台歌曲管理页表格操作列（`.col-actions`）MUST 默认仅展示一个「更多」（⋮）触发按钮。编辑、播放（试听）、下载、删除 MUST 全部位于该按钮展开的下拉菜单（`.table-more-menu`）内，不得在行内并列展示独立的编辑/播放/下载快捷图标按钮。当曲目无浏览器可播音频时，菜单内播放项 MUST 为 disabled 并保留不可播原因提示（与现有 `songHasWebPlayableAudio` 语义一致）。删除 MUST 仍为菜单内危险操作项。

#### Scenario: 操作列仅显示更多按钮

- **GIVEN** 歌曲管理页列表已加载且存在至少一条歌曲
- **WHEN** 用户查看任意行的操作列
- **THEN** 可见的操作控件仅为「更多」（⋮）按钮
- **AND** 不存在独立的编辑、播放、下载行内图标按钮

#### Scenario: 从更多菜单编辑

- **GIVEN** 用户点击某行「更多」并展开菜单
- **WHEN** 用户点击菜单项「编辑」
- **THEN** 系统打开该曲右侧编辑抽屉
- **AND** 该行高亮为当前活动行（若现有行为存在）

#### Scenario: 从更多菜单播放

- **GIVEN** 某曲存在浏览器可播音频格式
- **WHEN** 用户从更多菜单选择「播放」或「试听」
- **THEN** 系统调用现有后台播放流程并开始播放
- **AND** 底部播放器展示当前曲名与播放状态

#### Scenario: 不可播曲目菜单播放禁用

- **GIVEN** 某曲无可浏览器播放的音频文件
- **WHEN** 用户展开该行的更多菜单
- **THEN** 播放/试听菜单项为 disabled
- **AND** 用户无法通过该菜单项触发播放

#### Scenario: 从更多菜单下载

- **GIVEN** 某曲存在可下载文件
- **WHEN** 用户从更多菜单选择「下载」
- **THEN** 系统触发与现有 `startDownloadFlow` 等价的下载流程

### Requirement: 后台歌曲管理页编辑抽屉影视剧字段

编辑歌曲右侧抽屉主表单 MUST 在可见区域提供「影视剧」文本输入字段，绑定歌曲 `film_tv` 属性。该字段 MUST NOT 仅存在于 `adm-hidden-filters` 或其他默认折叠隐藏区。保存元数据时 MUST 将输入值写入现有歌曲更新 API 的 `film_tv` 字段（空字符串视为清空）。

#### Scenario: 打开抽屉可见影视剧输入

- **AND** 无需展开隐藏筛选区即可编辑该字段

#### Scenario: 保存并回显影视剧

- **WHEN** 用户再次打开该曲编辑抽屉
- **THEN** 影视剧输入框显示「琅琊榜」

### Requirement: 后台歌曲管理页编辑抽屉发行日期选择器

编辑抽屉中「发行日期」字段 MUST 使用日期选择器交互（如 HTML `input type="date"`），而非自由文本输入为主路径。表单与 API 之间 MUST 以 `YYYY-MM-DD` 格式字符串交换 `release_date`（与现有后端字段一致）。打开抽屉时 MUST 将歌曲已有 `release_date` 规范化为日期选择器可接受的值；无法解析的历史值 MAY 清空并允许用户重新选择。

### Requirement: 后台歌曲管理页编辑抽屉主内容区全高布局

后台壳内歌曲管理页右侧编辑面板（`#adminEditPanel` / `.admin-edit-panel`）在打开状态（`.is-open`）时 MUST 纵向占满**右侧主内容区**可用高度：顶边与主内容区顶边（视口 `top: 0`）对齐，底边与固定底部播放器上沿对齐（`bottom: var(--adm-player-total-h)` 或等价计算）。高度语义 MUST NOT 仅限 `.adm-workspace` 表格行区域。

面板 MUST 采用纵向 flex：`.drawer-head` 与 `.drawer-footer` 不随正文滚动；`.drawer-body-scroll` MUST 占据剩余高度并在溢出时内部纵向滚动（含 `min-height: 0` 约束）。

抽屉打开时，主内容（页头、工具栏、表格区）MUST 在右侧预留与抽屉等宽的布局空间（如 `margin-right: var(--adm-edit-w)`），避免列表被抽屉遮挡。抽屉 MUST NOT 覆盖左侧导航侧栏。

#### Scenario: 抽屉与主内容区同高

- **GIVEN** 用户在歌曲管理页打开某首歌曲的编辑抽屉
- **WHEN** 面板处于 `.is-open` 状态
- **THEN** 抽屉从视口顶边延伸至固定播放器上沿
- **AND** 抽屉高度大于仅含表格的 `.adm-workspace` 区域（覆盖页头/工具栏对应的右侧纵向空间）

#### Scenario: 长表单内部滚动且底栏固定

- **GIVEN** 编辑抽屉已打开且元数据与音频文件列表总高度超出面板可视区
- **WHEN** 用户在抽屉正文区域滚动
- **THEN** 仅 `.drawer-body-scroll` 滚动
- **AND** 抽屉标题栏与底部「取消」「保存」按钮保持可见

#### Scenario: 打开抽屉时主内容不被遮挡

- **GIVEN** 用户打开编辑抽屉
- **WHEN** 用户查看左侧页头、工具栏与歌曲表格
- **THEN** 上述区域不被抽屉覆盖
- **AND** 表格与分页仍可完整交互（右侧留出抽屉宽度）

#### Scenario: 侧栏折叠时抽屉仍贴主内容区右缘

- **GIVEN** 用户折叠后台侧栏后打开编辑抽屉
- **WHEN** 面板处于打开状态
- **THEN** 抽屉右缘贴视口右缘、左缘不侵入侧栏区域
- **AND** 底边仍对齐播放器上沿

### Requirement: 后台歌曲管理页编辑抽屉无保存草稿

编辑抽屉底部操作区 MUST NOT 提供「保存草稿」按钮或等价的本地草稿保存入口。底部 MUST 仅保留「取消」与「保存」（或语义等价的关闭与提交元数据操作）。客户端 MUST NOT 因用户编辑元数据而向 `localStorage` 写入 `adm-draft-*` 草稿键。

#### Scenario: 抽屉底部无保存草稿

- **GIVEN** 用户打开某首歌曲的编辑抽屉
- **WHEN** 用户查看底部操作栏
- **THEN** 不存在「保存草稿」按钮
- **AND** 可见「取消」与「保存」按钮

#### Scenario: 编辑过程不写入本地草稿

- **GIVEN** 用户在编辑抽屉中修改歌曲名但未点击保存
- **WHEN** 用户点击「保存草稿」（若存在）或等价草稿触发控件
- **THEN** 该控件不存在，无法触发
- **AND** 关闭抽屉后再次打开仍显示服务端已保存数据（除非用户曾点击「保存」）

### Requirement: 后台歌曲管理页编辑抽屉可编辑时长

编辑抽屉主表单中的「时长」字段 MUST 允许用户直接编辑，不得以只读控件作为唯一输入方式。展示与输入格式 MUST 为 `mm:ss`（分钟与秒以冒号分隔；秒为两位 00–59）。打开抽屉时 MUST 将歌曲 `duration_ms` 格式化为 `mm:ss` 填入该字段；无时长时 MAY 显示空或占位，与保存语义一致。用户点击保存元数据时，客户端 MUST 将合法输入解析为毫秒整数并写入歌曲更新 API 的 `duration_ms` 字段；输入为空时 MUST 提交清空时长（`null`）；`00:00` MUST 表示 0 毫秒。格式不合法时 MUST 阻止提交并以 Toast 或等价方式提示用户。

#### Scenario: 打开抽屉显示可编辑时长

- **GIVEN** 用户打开某首歌曲的编辑抽屉且该曲 `duration_ms` 为 225000
- **WHEN** 抽屉表单加载完成
- **THEN** 时长输入框可聚焦与编辑
- **AND** 其值为 `03:45` 或经规范化后的等价 `mm:ss` 表示

#### Scenario: 保存合法时长

- **GIVEN** 用户在时长字段输入 `4:05` 或 `04:05`
- **WHEN** 用户点击保存且其它校验通过
- **THEN** 客户端向歌曲更新 API 提交 `duration_ms` 为 245000
- **AND** 保存成功后列表与再次打开抽屉时展示更新后的时长

#### Scenario: 保存空时长表示未知

- **GIVEN** 用户将时长字段清空
- **WHEN** 用户点击保存
- **THEN** 客户端提交 `duration_ms` 为 null（或 API 约定的清空语义）
- **AND** 保存成功

#### Scenario: 非法格式阻止保存

- **GIVEN** 用户在时长字段输入 `3:99` 或 `abc` 等非 `mm:ss` 合法值
- **WHEN** 用户点击保存
- **THEN** 客户端不发起歌曲更新请求（或请求前拦截）
- **AND** 用户收到时长格式错误的提示

### Requirement: 后台歌曲管理页 Studio 风格底部播放器

后台歌曲管理页（`admin-page-music`）底部 MUST 提供与前台音乐库结构对齐的 Studio 风格播放器（`.studio-player`），包含：当前曲封面占位/缩略、曲名与艺人（或等价元数据）、播放/暂停、上一首、下一首、播放模式选择、可交互进度条与当前/总时长、音量控制。音频元素 MUST 隐藏原生 `controls`，由自定义 UI 驱动。播放器 MUST 接入现有后台播放队列与 `playSongInAdmin`（或等价）逻辑；播放、暂停、切歌、模式切换行为 MUST 与变更前后台播放能力一致或更强。歌曲列表主内容区 MUST 预留足够底部内边距，避免最后一行被固定播放器遮挡。

#### Scenario: 播放后播放器展示元数据

- **GIVEN** 用户从列表更多菜单或等效入口播放某曲
- **WHEN** 播放成功开始
- **THEN** 底部播放器显示该曲曲名
- **AND** 播放/暂停按钮反映正在播放状态
- **AND** 进度条随播放推进

#### Scenario: 播放暂停与切歌

- **GIVEN** 当前正在播放队列中某曲
- **WHEN** 用户点击播放器暂停按钮
- **THEN** 音频暂停且按钮变为播放态
- **WHEN** 用户点击下一首
- **THEN** 播放队列中下一可播曲目并开始播放（遵循当前播放模式）

#### Scenario: 音量与进度 seek

- **GIVEN** 播放器正在播放
- **WHEN** 用户拖动音量滑块
- **THEN** 音频音量相应变化
- **WHEN** 用户点击或拖动进度条
- **THEN** 播放位置跳转到对应时间点

#### Scenario: 列表不被播放器遮挡

- **GIVEN** 歌曲列表有多页数据且滚动至底部
- **WHEN** 用户查看最后一行
- **THEN** 最后一行完整可见且不被固定底部播放器覆盖

### Requirement: 前台曲库与歌单详情列表中当前播放行可见且不被子表头遮挡

前台壳内音乐库表格（`#songList` 所在 `.song-table-wrap`）及歌单详情歌曲子表（`playlistDetailSongList` 所在等价滚动容器）中，当某行被标记为当前正在播放（如 `tr.is-active` 或等价）且列表实施纵向滚动时，系统在将播放行滚入可视区域的过程中 MUST 扣除该滚动容器内 sticky 表头（`thead`）占用的高度，使播放行数据单元格完整出现在表头下方可见带内，而不得将行顶边与滚动容器顶边对齐导致行被表头覆盖。

#### Scenario: 音乐库切歌后播放行不被表头挡住

- **GIVEN** 用户在前台音乐库且列表行数超出滚动容器高度，表头为 sticky
- **WHEN** 用户通过上一首或下一首使另一首歌曲成为当前播放行
- **THEN** 播放行在容器内完整可见
- **AND** 该行任一数据列（含冻结列）不被 `thead` 遮挡

#### Scenario: 歌单详情子表切歌后同样不遮挡

- **GIVEN** 用户打开某歌单详情且歌曲子表可纵向滚动
- **WHEN** 用户切歌使播放行变化
- **THEN** 系统对歌单子表应用与音乐库相同的「扣除表头高度」滚动策略
- **AND** 播放行完整出现在子表 sticky 表头之下

### Requirement: 前台与服务端分页一致时切歌自动翻到含曲页

当前台曲库列表使用 `offset`/`limit` 分页且播放队列与当前页数据同源时，若用户通过上一首、下一首或曲目结束自动续播使「下一首」对应歌曲不在当前已加载页，客户端 MUST 将当前页码调整为包含该曲的页并重新请求列表数据，待列表渲染后再应用播放行高亮与「扣除表头」的滚动逻辑。

#### Scenario: 下一首在其它页时自动跳页

- **GIVEN** 曲库总数大于每页条数且当前不在最后一页，或当前播放曲不在本页边界场景下下一目标在邻页
- **WHEN** 用户触发下一首且目标曲仅出现在另一分页结果中
- **THEN** 客户端切换到正确页码并加载该页列表
- **AND** 目标曲所在行成为播放高亮行且滚动后完整可见

### Requirement: 后台列表区分正在播放与编辑选中且播放态与前台一致

后台歌曲管理页表格中，客户端 MUST 使用可区分的行态表示「当前正在播放」（由 `currentPlayIndex` 与 `playQueue` 驱动，如 `is-playing`）与「当前编辑上下文选中」（打开编辑抽屉或点击行编辑所对应歌曲，如 `is-active`）。正在播放行视觉强度 MUST 不低于前台音乐库播放行（同色阶意图：紫系背景、冻结列各 `td` 实色背景、无透底）。编辑选中行 MUST 使用明显弱于播放行的视觉（背景色对比低于播放行，且不得对行内每个数据列重复施加左侧 accent 竖条）。编辑选中行 MAY 仅在行首冻结列（如勾选列）保留至多一条左侧 accent 指示，或仅通过略深背景区分；中间列与操作列 MUST NOT 各自出现独立的紫色竖线。若编辑选中曲与正在播放曲为同一行，则 MUST 仅展示播放态，不得叠加编辑态竖条或双重描边。

#### Scenario: 仅播放时可见播放行态

- **GIVEN** 管理员未点击任意行打开编辑
- **WHEN** 用户从更多菜单试听某曲且播放成功
- **THEN** 对应该曲的数据行展示「正在播放」行态
- **AND** 不错误复用「仅编辑选中」态作为播放反馈

#### Scenario: 编辑另一首时仍高亮正在播放

- **GIVEN** 歌曲 A 正在播放，用户点击歌曲 B 行打开编辑抽屉
- **WHEN** 列表仍显示 A 与 B 两行
- **THEN** A 行保持「正在播放」态
- **AND** B 行展示「编辑选中」较弱态（或等价可辨样式）

#### Scenario: 编辑选中行无每列竖条

- **GIVEN** 用户点击某行打开编辑且该行未在播放
- **WHEN** 用户横向浏览表格各列（含冻结列与中间列）
- **THEN** 任意两列之间不得因编辑选中而出现并列的多条紫色竖线
- **AND** 若存在左侧 accent，则整行至多一条且位于行首冻结列区域

#### Scenario: 后台播放行滚动可见且不受表头遮挡

- **GIVEN** 后台列表滚动容器为 `.adm-table-scroll` 且表头 sticky
- **WHEN** 正在播放行不在可视区内或部分被表头遮挡
- **THEN** 客户端滚动容器使该行完整出现在表头下方
- **AND** 滚动计算扣除 `thead` 高度（与前台方案 A 同意图）

### Requirement: 后台切歌跨页时自动加载正确页

当后台播放队列与当前分页列表同源且下一首/上一首/自动续播目标曲不在当前 `songPage` 所加载集合中时，客户端 MUST 调整 `songPage` 并重新请求列表，使目标曲出现在表格中后再应用播放行态与滚动。

#### Scenario: 后台下一首触发翻页

- **GIVEN** 后台曲库分页且当前播放索引指向将切至另一页所含歌曲
- **WHEN** 用户点击播放器下一首
- **THEN** 列表跳转到该曲所在页并展示该行播放态
- **AND** 该行在 `.adm-table-scroll` 内完整可见

## Notes

- 前台与后台壳内存在大量业务控件与区域显隐；子视图多数由脚本内存状态驱动，**不**依赖浏览器地址栏路径片段区分（与采用 History 路由的单页应用不同）。
- 样式表与脚本链接上的版本查询参数（如 `?v=`）仅用于缓存刷新，数值随发布变更，不作为对外契约字段。
- 当前服务端实现中：静态资源挂载前缀为 `/static`，站点根路径为 `/`，管理入口路径为 `/admin`；若反向代理改写前缀，以部署为准。
- 前台模块内 **唯一** 封装的数据请求入口会转发至浏览器网络请求；模块脚本文件本身仍可再拆分或由运行时加载其它片段，但 HTML 仅声明一条模块脚本入口。

## Known Gaps

- **未挂载脚本**：静态目录中存在额外的客户端脚本文件（如 `app.js`），**未被**前台或后台 HTML 引用；是否仍供手工或其它构建流程使用，本规范不承诺。
- **壳内占位与装饰**：部分主导航或分层 Tab 在界面中呈禁用或静态文案（如「暂未开发」、示意存储用量），其与服务端数据的一致性未在壳层规范中定义为实时接口驱动。
- **第三方字体**：壳文档依赖公网字体样式表；离线或受限网络下的降级表现取决于浏览器，未在代码中单独处理。
- **入口文件缺失或不可读**：若静态目录中缺少 `index.html` / `admin.html` 或进程无读取权限，对应入口路由可能返回错误响应；具体状态码与正文依赖服务端与部署，未在壳层单独约定。
