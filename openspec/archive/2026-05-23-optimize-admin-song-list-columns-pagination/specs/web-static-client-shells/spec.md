## ADDED Requirements

### Requirement: 后台歌曲管理页列表表格列与顺序

后台壳内歌曲管理页主表格 SHALL 按下列顺序展示列（不含行首勾选列）：歌曲、原唱、作词、作曲、专辑、语言、标签、格式、时长、发行日期、元数据、创建时间、更新时间、操作。

各列展示规则 SHALL 为：

| 列 | 数据来源 / 展示 |
|----|-----------------|
| 歌曲 | 歌曲标题；无副文案时长（时长独立列） |
| 原唱 | `lead_artist` 或等价主唱展示串 |
| 作词 | 词作者名字列表，以「、」或「 / 」连接 |
| 作曲 | 曲作者名字列表，以「、」或「 / 」连接 |
| 专辑 | 专辑名 |
| 语言 | 语言展示名 |
| 标签 | 标签名列表 |
| 格式 | 代表性音频格式标签 |
| 时长 | `duration_ms` 格式化为 `mm:ss` |
| 发行日期 | `release_date` 原文或格式化展示 |
| 元数据 | 元数据完成度进度条与百分比 |
| 创建时间 | `created_at` 本地化展示 |
| 更新时间 | `updated_at` 本地化展示 |
| 操作 | 见「后台歌曲管理页列表操作按钮」 |

表格 MUST NOT 包含「年份」「封面」「状态」「歌词」列。

支持排序的列（若实现表头排序）SHALL 与上述字段对应，且排序请求参数与曲库列表 API 的 `sort_by` 一致。

#### Scenario: 列顺序与必填字段展示

- **GIVEN** 歌曲管理页已加载且列表至少一条记录
- **WHEN** 用户查看表头
- **THEN** 表头从左至右（勾选列之后）依次为歌曲、原唱、作词、作曲、专辑、语言、标签、格式、时长、发行日期、元数据、创建时间、更新时间、操作
- **AND** 不出现年份、封面、状态、歌词列

#### Scenario: 空字段占位

- **GIVEN** 某歌曲缺少作词或作曲关联
- **WHEN** 渲染该行
- **THEN** 对应单元格显示「—」或等价占位

### Requirement: 后台歌曲管理页列表操作按钮

操作列 SHALL 提供编辑、播放、下载三类主操作：编辑打开编辑抽屉；播放仅在存在可浏览器试听的音频时可用；下载打开格式选择或直链下载流程（与现有单曲下载行为一致）。删除等破坏性操作 MAY 保留在「更多」菜单中。

#### Scenario: 可播放歌曲显示播放

- **GIVEN** 列表行对应歌曲存在可 Web 试听的音频变体
- **WHEN** 用户查看操作列
- **THEN** 播放操作可用
- **AND** 激活后发起试听（与现有 `play` 流程一致）

#### Scenario: 不可播放时禁用或隐藏播放

- **GIVEN** 列表行对应歌曲无可 Web 试听变体
- **WHEN** 用户查看操作列
- **THEN** 播放操作不可用或不出现在主操作区

### Requirement: 后台歌曲管理页服务端分页与总数展示

歌曲管理页列表数据 MUST 通过曲库列表 API 的 `offset` 与 `limit` 分页获取，不得依赖一次性拉取固定上限（如 500）后在客户端切片作为唯一分页来源。页脚分页控件切换页码或每页条数时 MUST 重新请求当前页数据。

页脚 SHALL 展示当前筛选条件下的歌曲总数文案（如「共 N 首」）。页面顶部「音乐总数」统计卡片 SHALL 展示全库歌曲条数（`library_total`），与是否应用筛选无关。

快速筛选、关键词、排序变更时 MUST 将页码重置为第 1 页并重新请求列表。

#### Scenario: 翻页请求服务端

- **GIVEN** 筛选后 `total` 大于每页条数
- **WHEN** 用户点击下一页
- **THEN** 客户端以更新后的 `offset` 请求列表 API
- **AND** 表格仅展示该页 `items`

#### Scenario: 展示筛选总数与全库总数

- **GIVEN** 全库 1000 首，当前筛选命中 42 首
- **WHEN** 列表加载完成
- **THEN** 页脚显示共 42 首（或等价文案）
- **AND** 顶部音乐总数显示 1000

#### Scenario: 筛选变更重置页码

- **GIVEN** 用户当前在第 3 页
- **WHEN** 用户变更任一快速筛选或关键词
- **THEN** 页码重置为 1
- **AND** 列表与 `total` 反映新筛选条件

## MODIFIED Requirements

### Requirement: 后台歌曲管理页快速筛选可搜索多选

后台壳内歌曲管理页的「更多筛选」面板 SHALL 为原唱、作词、作曲、标签、格式、语言六个维度提供可搜索的多选下拉；用户 MUST 能通过关键字模糊匹配选项，并勾选或取消勾选多项；同一维度内多选为 OR，不同维度之间为 AND。原唱、作词、作曲、标签、语言五个维度的可选项来源 SHALL 符合「后台歌曲管理页快速筛选选项来源」要求。筛选条件 MUST 通过曲库列表 API 查询参数提交并在服务端生效，而非仅在已加载的客户端数组上过滤。

#### Scenario: 勾选后状态保持

- **GIVEN** 用户已打开「更多筛选」并展开某一维度的下拉
- **WHEN** 用户勾选或取消勾选某一选项
- **THEN** 该选项的勾选状态立即反映在 checkbox 上
- **AND** 关闭并再次打开下拉后勾选状态与之一致
- **AND** 触发器文案反映当前选中（未选时显示维度名称，选中一项时显示该项名称，选中多项时显示合并文案或计数）

#### Scenario: 搜索过滤选项

- **GIVEN** 某维度下拉已展开且存在多个可选项
- **WHEN** 用户在搜索框输入关键字
- **THEN** 仅显示标签或值与关键字模糊匹配的选项
- **AND** 对可见选项的勾选/取消勾选仍正确更新筛选结果

#### Scenario: 筛选结果更新

- **GIVEN** 用户已在至少一个维度选中一个或多个选项
- **WHEN** 选中集合发生变化
- **THEN** 客户端重新请求列表 API，歌曲列表仅显示满足各维度 OR/AND 规则的歌曲
- **AND** 「重置」按钮可见且可清空所有快速筛选与关键词

#### Scenario: 翻页不重建筛选项

- **GIVEN** 用户已在快速筛选中选中若干选项
- **WHEN** 用户切换列表页码或修改每页条数
- **THEN** 快速筛选的选中状态与触发器文案保持不变
- **AND** 下拉选项列表不因表格重绘而被清空或重置

#### Scenario: 曲库或参考数据变更后刷新选项

- **GIVEN** 曲库歌曲集合发生变更（如扫描完成、重新加载歌曲列表），和/或艺人、标签、语言管理数据发生变更
- **WHEN** 客户端完成相应数据刷新
- **THEN** 各维度下拉选项列表更新为与当前数据源一致的集合（艺人/标签/语言按管理列表，格式按曲库文件格式）
- **AND** 仍保留当前仍存在于新选项列表中的已选值

#### Scenario: 单选项维度可有效勾选

- **GIVEN** 某筛选维度在当前可选项中仅有一个选项
- **WHEN** 用户勾选该唯一选项
- **THEN** 该选项保持勾选状态
- **AND** 客户端重新请求列表且结果按该条件过滤
- **AND** 触发器显示该选项名称而非仅显示维度名称
