## ADDED Requirements

### Requirement: 前台壳底部播放器紧凑两行布局

前台壳底部固定播放器（`.studio-player`）SHALL 采用 **两行** 纵向结构，且整个播放器占用高度 MUST 明显低于改版前三列 + 中列纵向堆叠的实现。

- **第一行（控制行）** SHALL 容纳现有播放器能力：曲目封面与曲名/艺人展示、上一首/播放暂停/下一首、播放模式下拉、播放进度条与当前/总时长、音量控制，以及既有右侧辅助按钮（播放当前列表、词、全屏等，若页面中仍存在）。
- **第二行（歌词行）** SHALL **仅** 展示歌词同步/占位文案（`#playerLyricLine`），横跨播放器主内容宽度；MUST NOT 将歌词与控制按钮、进度条置于同一行。

控制行内控件 SHOULD 以单行横向排列为主；允许在窄视口下控制行 **内部** 换行，但 MUST NOT 将 transport、进度条、歌词拆成三行纵向堆叠（即不得复现「transport 一行 + 进度一行 + 歌词一行」均在控制区内的布局）。

播放器 `position: fixed` 与 `left` 随侧栏展开/收起同步过渡的行为 MUST 保持不变。

主内容滚动区域（含音乐库列表）SHALL 预留底部内边距（或等效布局），其值 MUST 不小于压缩后播放器实际高度，确保列表最后一行不被播放器遮挡。

#### Scenario: 播放器仅两行可见结构

- **GIVEN** 用户打开前台壳并查看底部播放器
- **WHEN** 用户观察播放器垂直结构
- **THEN** 可见区域由上至下仅为控制行与歌词行共两行
- **AND** 歌词文案出现在控制行下方独立一行

#### Scenario: 控制行包含既有播放能力

- **GIVEN** 用户正在播放一首可试听曲目
- **WHEN** 用户查看控制行
- **THEN** 可见播放/暂停、上一首、下一首与播放模式下拉
- **AND** 可见进度条与当前时间、总时长
- **AND** 可见音量滑块与曲名/艺人信息

#### Scenario: 歌词行独占第二行

- **GIVEN** 用户正在播放曲目
- **WHEN** 用户查看 `#playerLyricLine` 所在区域
- **THEN** 该行位于控制行之下
- **AND** 该行不包含 transport 按钮或进度条元素

#### Scenario: 列表末行不被播放器遮挡

- **GIVEN** 用户处于音乐库视图且列表可纵向滚动
- **WHEN** 用户滚动至列表最后一行
- **THEN** 最后一行完整可见于播放器上缘之上
- **AND** 不被固定底栏遮挡

#### Scenario: 侧栏收起时播放器宽度同步

- **GIVEN** 用户通过侧栏折叠控件收起左侧导航
- **WHEN** 过渡动画结束
- **THEN** 底部播放器 `left` 与主内容区对齐窄侧栏
- **AND** 两行布局仍保持控制行在上、歌词行在下
