# 个人音乐管理平台：产品定位、规划与当前能力

## 1. 产品定位（Product Positioning）

### 1.1 产品定义
一个 **个人专属、Local-first（本地优先）** 的音乐管理平台，面向用户自有音乐文件，提供统一的导入、整理、在线试听、格式选择下载能力，并区分 **前台播放端** 与 **后台管理端**。

### 1.2 目标用户
- 有本地音乐收藏习惯的个人用户（电脑/NAS/移动硬盘）
- 对音质和文件管理有要求（同曲多格式、元数据完整）
- 希望像流媒体一样使用自己的音乐库

### 1.3 核心价值
- **统一管理**：多目录音乐文件集中索引，避免散乱
- **高效找歌**：按歌名、原唱、专辑、**风格**、标签、语言、格式及作词/作曲等快速检索
- **顺滑试听**：浏览器内在线播放、队列播放、播放模式切换
- **便捷下载**：单曲/批量按**可选格式（多选）**下载，后端同源代理避免浏览器拦截
- **同曲多格式并存**：同一歌曲可同时管理 FLAC/MP3/AAC/WAV 等版本
- **元数据可治理**：后台支持**右侧抽屉**编辑、**影视剧**等扩展字段，手工维护后保存
- **曲库运维**：合并所选歌曲、按元数据**同步对象存储路径**、跳过文件原因可见
- **前后台分离**：前台聚焦播放体验，后台聚焦扫描、筛选、批量治理与元数据维护

### 1.4 产品边界
- 管理用户自有音乐文件，不内置公域曲库
- 默认单用户场景，不强制登录
- 默认不改动源文件，仅建立索引（可后续扩展"整理模式"）

## 2. 产品规划（Product Planning）

### 2.1 功能架构（与当前实现对齐）

1) 音乐库管理
- 指定本地目录扫描导入（浏览器目录选择器）或**批量选择文件**添加；扫描过程**进度展示**；**跳过文件原因**可弹窗查看
- 歌曲、专辑、艺人、标签、语言、**风格**多维管理；元数据含标题、**原唱**、作词、作曲、专辑、**影视剧**、**风格（多选）**、语言（多选）、标签、发布日期、时长及文件侧码率/采样率等
- 库内时间展示统一为**上海时区（Asia/Shanghai）**

2) 同曲多格式管理（核心能力）
- 同一逻辑歌曲（Song）下多行音频文件（SongFile）
- 列表/详情展示各版本格式、码率、采样率、位深、声道、大小等
- 试听与下载可按行或按策略选择格式；**默认优先级可配置**（如无损优先）

3) 在线试听
- 网页播放器、播放队列、顺序/随机/列表循环/单曲循环
- 进度拖动（HTTP Range）；优先可网页播放格式

4) 下载能力
- **单曲与批量**均支持**格式多选**；多文件时服务端 **ZIP**；**文件命名规则**已统一优化
- 后端同源代理下载

5) 搜索与筛选
- 关键词搜索（支持**一键清空**）；筛选条件支持**重置**
- 覆盖歌名、原唱、专辑、作词、作曲及**影视剧**（接口侧）等；筛选含格式、原唱、作词、作曲、标签、语言、**风格**等
- **同一筛选项内多选为「或」**（如多选标签：命中**任一**所选标签即可）；**不同筛选项之间为「与」**（须同时满足各已选维度）

6) 后台管理
- 音乐列表：多列展示与**列头排序**；操作列固定；**批量删除**、**批量下载**、**合并所选歌曲**（自选保留主记录）、**同步存储路径**（进度反馈）
- **编辑歌曲**：**右侧抽屉**（非弹窗）；原唱/作词/作曲/语言/风格**多选 + 模糊搜索**；单首歌多文件行内试听/下载/重命名/删除/**添加文件**；添加文件失败展示原因；添加文件时可**保留未保存的编辑内容**
- **风格管理**页（与标签/语言类似的列表、排序、批量删除、弹窗编辑）
- 艺人管理：多角色（歌手、作词、作曲）；标签/语言/风格管理支持搜索与行内操作

### 2.2 分阶段路线图

#### Phase 1（MVP）— 已完成
- 本地扫描/导入索引、同曲多格式、前台播放与歌单、后台列表与元数据维护、后端代理下载

#### Phase 2（体验增强）— 部分已完成
- **已完成**：风格字段与管理、风格多选筛选；批量删除/批量下载；**下载格式多选**与 ZIP；编辑抽屉与交互优化；合并所选歌曲；存储路径同步；跳过原因与失败原因提示；关键词清空与筛选重置；**影视剧**字段；前台/后台条件筛选多选语义与交互细化（同维度 OR、布局间距、searchable-select 整行可点等，见 **`iterations/20260401.md`**）
- **待办**：收藏、最近播放；增量扫描性能与稳定性；元数据写回音频文件；标签筛选「追加/移除」类体验细化

#### Phase 3（进阶能力）— 未开始
- 标签写回文件（可选）、目录实时监控、音频指纹聚合、多端/分享链接等

## 3. MVP 与当前能力（可落地）

### 3.1 MVP 目标（闭环定义）
在最短周期内完成"可用闭环"：
**导入本地音乐 -> 前台播放试听 -> 后台管理维护 -> 按格式下载（含批量）**。

### 3.2 当前已交付能力清单（P0+，与迭代一致）
- 支持格式：MP3、FLAC、M4A/AAC、WAV、OGG、ALAC 等（以实际扫描配置为准）
- 导入：后台**扫描目录**或**新增歌曲**（文件多选），带进度；跳过文件可查看原因
- 元数据：标题、**原唱**、作词、作曲、专辑、**影视剧**、**风格（多选）**、语言（多选）、标签、发布日期、时长；文件侧比特率、采样率、位深、声道等
- 同曲多格式：一首歌多条 `SongFile`；列表可选试听/下载所用格式
- 前台：歌单与歌曲卡片（原唱、作词、作曲、风格标签、专辑、时长、发行日期等；部分信息 hover 提示）；条件筛选**同维度多选为 OR**（如多标签任一命中），与 `GET /songs` 一致
- 播放：播放模式、上一首/下一首、进度拖动
- 下载：与后台一致的**格式多选**逻辑；批量 ZIP
- 后台表格：歌曲名、原唱、作词、作曲、专辑、**影视剧**、语言、风格、标签、发布日期、时长、格式/播放选择、**创建时间、更新时间**等；列排序；筛选可重置；关键词可清空
- 后台运维：批量删除、批量下载、**合并所选歌曲**、**同步存储路径**（带进度）
- 元数据编辑：**右侧抽屉**；多选下拉支持模糊搜索；音频文件行内管理
- 主数据管理：艺人（多角色）、标签、语言、**风格**（列表、排序、批量删除等）

### 3.3 关键交互（当前）

1) 建库与导入：后台「扫描目录」或「添加歌曲」→ 进度与结果摘要 → 跳过原因弹窗（若有）
2) 前台播放：歌单/全部歌曲 → 播放与模式切换 → 下载时选格式（多选）
3) 歌单：创建/改名/删除、拖拽排序，「全部歌曲」固定首位
4) 后台音乐管理：搜索、筛选、排序、行内「更多」试听/下载/编辑/删除；勾选后批量操作或合并、同步路径
5) 编辑歌曲：抽屉内改元数据与标签；多文件时行内试听/重命名/删除/添加文件；「保存元数据」写库
6) 艺人/标签/语言/风格：列表管理、搜索、弹窗新建编辑、部分支持批量删除

### 3.4 数据模型说明（摘要）

详细字段类型与中文含义以 **[技术实现方案.md](技术实现方案.md) 第 3 节**为准。产品侧需知要点：

- **Song**：逻辑歌曲；含 `album_id`、`language_id`/`genre_id`（与多选关联表同步的代表字段）、`release_date`、`film_tv`、`duration_ms` 等
- **SongFile**：对象存储键 `object_key`、哈希 `sha256`、格式与技术指标、是否无损/可网页播放等
- **多对多**：`song_lead_artists`（原唱）、`song_lyricist_artists`、`song_composer_artists`；语言 `song_languages`、风格 `song_genres`、标签 `song_tags`
- **PlaylistItem** 排序字段为 **`position`**（非 `sort_order`）
- **扫描作业**表为 `scan_jobs`（浏览器上传导入不一定写入；服务端扫盘接口会写入）

### 3.5 验收标准（延续 MVP 并兼容现状）
- 同一歌曲可聚合至少 2 种格式并可切换试听/下载格式
- 搜索与筛选在可接受数据量下操作流畅；试听可拖进度
- 下载走同源代理；批量多格式时 ZIP 可用
- 后台表格排序、搜索、筛选、重置可用；抽屉编辑保存后列表更新
- 合并所选歌曲、同步存储路径在典型场景下可用（失败时有提示）
- 1000 首规模下主观体验可接受（可作压测基线）

## 4. 技术实现建议（与仓库一致）

- 后端：Python + FastAPI；启动时 `ensure_schema` 做轻量结构补齐
- 数据库：SQLite（可换 PostgreSQL/MySQL，ORM 已抽象）
- 对象存储：S3 / MinIO；音频路径规则随元数据变更可 **copy + 删旧键**（同步路径能力）
- 前端：静态 HTML + 原生 JavaScript + CSS（前台 `index.html`，后台 `admin.html`）
- 播放：HTML5 Audio + 后端流式代理 + Range
- 元数据解析：mutagen
- 安全：通过 `song_file_id` 等访问文件，不暴露对象存储真实路径给浏览器
- 详设见 **[技术实现方案.md](技术实现方案.md)**

## 5. 风险与设计要点

- 同曲聚合准确率：仅靠元数据可能误判，需结合时长等规则；长期可考虑指纹
- 浏览器格式兼容：部分无损格式需降级策略
- 大库性能：扫描、分页/筛选、表格排序与批量操作需控制单次规模
- 文件变更一致性：外部删除/移动后需重导或后续「目录监控」类能力
- 艺人多角色：歌手/作词/作曲在后台与前台展示一致；**前台已不展示合唱信息**（若历史数据仍存在，以界面为准）
- 标签/风格治理：命名冲突、重复项需后台约束与清理习惯
- **合并歌曲 / 同步存储路径**：属高风险运维操作，需明确失败提示与回滚预期（以当前产品提示为准）

## 6. UI/UX 设计要点

### 6.1 前台（播放器）
- 歌单列表：拖拽排序，「全部歌曲」固定首位
- 歌曲列表：歌名、风格标签、格式、语言、标签、**原唱**、作词、作曲、专辑、时长、发行日期等；部分信息 **hover** 展示说明
- 布局：歌单栏与右侧内容区、条件筛选区与下方歌曲列表之间保留**适度间距**（见迭代 **`iterations/20260401.md`**）
- 筛选：格式、语言、标签；多选下拉为**搜索 + 复选框行**；**重置**筛选条件；关键词 **一键清空**；下拉内不设「全部（不筛选）」快捷行，清空依赖**重置**或逐项取消
- 播放器：列表循环、单曲循环、随机、顺序；上一首/下一首
- 操作：试听、加入歌单、**下载（多格式勾选，与后台逻辑一致）**、从歌单删除
- 统一组件：弹窗、Toast、按钮字号统一
- 时区：展示为**上海时区**

### 6.2 后台（管理界面）
- 布局：顶栏与表格区域宽度协调；表格**不换行**关键列；**操作列固定右侧**，「更多」菜单避免被裁切
- 音乐管理：筛选区**展开/收起**（默认收起）；条件筛选各字段为**可搜索多选下拉**（复选框行），与前台交互一致；**点击行内任意位置或复选框**均可切换勾选，且切换后须驱动列表刷新；下拉内不设「全部（不筛选）」快捷行，清空依赖**重置**或逐项取消（详见 **`iterations/20260401.md`**）
- 列头**排序**；**序号**列；**更新时间**；工具栏含批量删除/批量下载/**合并所选歌曲**/**同步存储路径**（进度）等
- 编辑歌曲：**右侧抽屉**（非居中弹窗）；原唱/作词/作曲/语言/风格 **多选**，支持 **模糊搜索**，下拉打开时点击外部收起；选项行 **hover 高亮**，可点击整行切换勾选
- 音频文件：抽屉内分行展示，行内试听/下载/重命名/删除；支持「添加文件」；失败原因 Toast/提示
- 艺人/标签/语言/**风格**：列表化、列排序、搜索、弹窗新建/编辑；部分支持批量删除；弹窗打开时焦点落在名称输入框
- 扫描：浏览器目录选择器或文件选择；进度条与跳过原因弹窗

## 7. 一句话版本
面向个人本地曲库：前台完成播放、歌单与**多格式下载**；后台完成导入与扫描进度、**表格化治理**（排序、筛选、重置、批量与合并、存储路径同步）、**抽屉化元数据编辑**（含**风格/语言多选**、**影视剧**），以「同曲多格式」与「艺人多角色」为底座，持续向写回文件、监控与指纹等进阶能力演进。
