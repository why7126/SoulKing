## ADDED Requirements

### Requirement: 后台歌曲管理页编辑抽屉可编辑时长

编辑抽屉主表单中的「时长」字段 MUST 允许用户直接编辑，不得以只读控件作为唯一输入方式。展示与输入格式 MUST 为 `mm:ss`（分钟与秒以冒号分隔；秒为两位 00–59）。打开抽屉时 MUST 将歌曲 `duration_ms` 格式化为 `mm:ss` 填入该字段；无时长时 MAY 显示空或占位，与保存语义一致。用户点击保存元数据时，客户端 MUST 将合法输入解析为毫秒整数并写入歌曲更新 API 的 `duration_ms` 字段；输入为空时 MUST 提交清空时长（`null`）；`00:00` MUST 表示 0 毫秒。格式不合法时 MUST 阻止提交并以 Toast 或等价方式提示用户。

#### Scenario: 打开抽屉显示可编辑时长

- **GIVEN** 用户打开某首歌曲的编辑抽屉且该曲 `duration_ms` 为 225000
- **WHEN** 抽屉表单加载完成
- **THEN** 时长输入框可聚焦与编辑
- **AND** 其值为 `03:45` 或经规范化后的等价 `mm:ss` 表示

#### Scenario: 保存合法时长

- **GIVEN** 用户在时长字段输入 `4:05` 或 `04:05`
- **WHEN** 用户点击保存且其它校验通过
- **THEN** 客户端向歌曲更新 API 提交 `duration_ms` 为 245000
- **AND** 保存成功后列表与再次打开抽屉时展示更新后的时长

#### Scenario: 保存空时长表示未知

- **GIVEN** 用户将时长字段清空
- **WHEN** 用户点击保存
- **THEN** 客户端提交 `duration_ms` 为 null（或 API 约定的清空语义）
- **AND** 保存成功

#### Scenario: 非法格式阻止保存

- **GIVEN** 用户在时长字段输入 `3:99` 或 `abc` 等非 `mm:ss` 合法值
- **WHEN** 用户点击保存
- **THEN** 客户端不发起歌曲更新请求（或请求前拦截）
- **AND** 用户收到时长格式错误的提示
