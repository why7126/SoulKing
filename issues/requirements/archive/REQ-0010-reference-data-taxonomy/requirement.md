# 参考数据与分类体系管理

## 背景
ProjectSoulKing 当前已在代码与已生效 OpenSpec 中实现 `reference-data-taxonomy` 能力。为避免需求状态只存在于对话或规格结果中，本需求将该能力回填到 `issues/requirements`，作为可审计的历史需求档案。

## 目标用户
- 个人音乐库维护者
- 管理员
- 已登录普通用户（适用于面向前台或账号自助的能力）

## 用户价值
定义「参考数据 / 分类体系」能力：通过服务端接口维护四类可控词汇——**标签**、**语言**、**风格**、**人物（艺人）**——的查询与增删改；并说明删除时对曲目关联数据的处理方式。人物除名称外还支持一组类型标签的读写。本规范仅描述当前已实现行为；曲目如何引用这些参考数据属于曲目元数据能力，不在此展开字段语义。

## 范围 In
- 覆盖 `reference-data-taxonomy` 已生效规格中的 16 个 Requirement。
- 以当前代码、OpenSpec 与产品文档描述的已实现行为为准。
- 保留规格中的 Notes 与 Known Gaps 作为后续演进输入。

## 范围 Out
- 不在本需求中新增接口、数据结构、权限边界或 UI 行为。
- 不直接修改 `openspec/specs/`，仅引用其作为已生效事实源。
- 不承诺修复 Known Gaps；后续若处理需另建 REQ/BUG 与 OpenSpec Change。

## Notes
- 创建与更新时的重名判断基于提交名称的大小写形式，持久化名称使用裁剪后的结果；首尾空白边缘输入可能导致与直觉不一致，调用方应避免依赖。
- 标签、语言、风格在创建与更新成功响应中通常仅显式返回标识与名称；响应体中的创建时间字段常为缺省空值。列表接口则为每条记录填充格式化的创建时间（若有底层时间戳）。
- 删除语言时，若库中原先仅有一条语言且其名称不是「普通话」，流程可能在删除前新增一条「普通话」语言作为替换基准，因而「删除前库内语言条数」与「是否允许删除」不能仅靠条数判断。

## Known Gaps
- **人物删除的完整性**：删除人物前仅清空曲目主记录上的两类艺人引用列；若其它关联数据仍引用该人物且数据库启用严格外键，删除是否成功取决于存储引擎与约束配置，本规范不承诺跨所有部署成功。
- **人物创建/更新响应中的时间字段**：成功响应往往不显式包含创建时间或更新时间，与列表接口字段完备程度不一致。
- **语言删除与「普通话」**：删除流程可能新增或依赖名为「普通话」的语言行；是否与某一请求中的删除目标冲突，取决于调用当下库内已有语言集合，不宜归纳为单一数目规则。
