## Why

后台歌曲管理页是运营人员日常维护曲库的核心界面。当前操作列同时展示编辑、播放、下载三个快捷图标与「更多」菜单，视觉拥挤且与前台音乐库「仅更多下拉」的交互不一致；编辑抽屉中「影视剧」字段被隐藏在折叠区、发行日期仍为纯文本输入，不利于完整元数据维护；底部播放器仅为带原生 `<audio controls>` 的紧凑条，缺少与前台音乐库一致的 transport、进度条、音量与播放状态展示，试听体验割裂。

## What Changes

- **操作列收敛**：歌曲列表操作列默认 **仅显示「更多」（⋮）按钮**；「编辑」「播放/试听」「下载」全部移入下拉菜单；「删除」保留在更多菜单内（与现有危险操作一致）。不可播放时菜单内播放项 disabled 并保留提示。
- **编辑抽屉字段优化**：
  - 将 **影视剧**（`film_tv`）字段移入主表单可见区域，提供文本输入，保存时写入现有 API 字段。
  - **发行日期** 交互改为 **日期选择器**（`<input type="date">` 或等效原生/轻量 date picker），与后端 `release_date` 字符串（如 `YYYY-MM-DD`）互转；移除「手动输入任意格式」为主路径。
- **后台播放器升级**：在歌曲管理页底部引入与前台音乐库 **结构对齐** 的 `.studio-player` 播放器（封面/曲名艺人、播放暂停、上一首/下一首、播放模式、进度条与时间、音量）；隐藏原生 audio controls，复用现有 `playSongInAdmin` / 播放队列逻辑；主内容区预留底部高度避免遮挡。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `web-static-client-shells`：补充后台歌曲列表操作列「仅更多」下拉、编辑抽屉影视剧可见与发行日期选择器、后台歌曲管理页 Studio 风格底部播放器等壳层行为与验收场景。

## Impact

- **前端**：`app/static/admin.html`（操作列 DOM、编辑抽屉表单、底部播放器结构）、`app/static/admin.js`（行操作菜单项与事件、发行日期同步、播放器 UI 绑定与进度/音量/播放暂停）、`app/static/admin-studio.css`（操作列宽度、播放器样式，可复用/扩展 `studio.css` 中 `.studio-player` 规则）。
- **后端 / API**：无契约变更（`film_tv`、`release_date` 字段已存在）。
- **关联变更**：与已存在的 `optimize-admin-song-edit-drawer`（艺人/标签/格式抽屉优化）互补，本变更聚焦操作列、影视剧/日期与播放器，不重复抽屉多选改造。
