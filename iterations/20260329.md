## 1. 后台歌曲元数据：原唱 / 作词 / 作曲（飞书式多选）

### 目标

在元数据抽屉中，三个艺人字段在「搜索 + 筛选」基础上，支持 **输入即新建**、**同名艺人补全类型**，且选项按 **本机最近使用** 排序（多维表格式多选体验）。

### 行为摘要

| 能力 | 说明 |
|------|------|
| 搜索 / 模糊筛选 | 沿用 `fuzzyMatchName`；有搜索词时仍展示已勾选项，避免「选了却找不到」。 |
| 最近使用排序 | `localStorage` 键 **`pm_admin_artist_recent_v1`**，内按角色 `lead` / `lyricist` / `composer` 分别记录 `艺人 id → 时间戳`；下拉列表按时间 **降序**，再按中文名排序。 |
| 勾选与保存 | 勾选某艺人时 `touchArtistRecent`；**保存元数据**成功后 `recordMetadataArtistRecent` 批量刷新三个角色的最近使用。 |
| 新建艺人 | 搜索框内容与库中 **无完全同名**（忽略大小写）时，展示 **「创建并添加「…」」**，点击或 **回车** → `POST /people`，`types` 分别为该列对应类型（原唱=`歌手`，作词=`作词`，作曲=`作曲`），并自动勾选。 |
| 补全类型 | 库中 **已有同名** 但 **当前列类型未包含**（例如仅有「歌手」却在「作词」中搜索）时，展示 **「将「…」添加为「作词」」** 等 → `PUT /people/{id}` 合并 `types`。 |
| 数据与展示 | 已选 ID 以 **`state.people`** 为准校验与展示 chip，避免「仅带单一类型」的艺人被误过滤；选项与标签中的名称使用 **`escapeHtmlUserText`** 转义。 |

### 主要文件

- `app/static/admin.js`：`artistRoleKeyFromType`、`buildCandidatePeopleForField`、`renderArtistMultiSelect` 重写、`recordMetadataArtistRecent`、`saveSingleMetadata` 内调用等。
- `app/static/styles.css`：`.multi-select-meta-row`、`.multi-select-meta-hint`、`.is-busy` 等（与语言/风格共用）。
- `app/static/admin.html`：静态资源版本号随构建 bump（见第 4 节）。

## 2. 后台歌曲元数据：语言 & 风格（同一套交互）

### 与艺人字段的差异

- 语言、风格 **无「类型」维度**：仅 **完全同名则不出现新建行**；否则提供 **「创建并添加」** → **`POST /languages`** / **`POST /genres`**。
- 最近使用分别使用 **`pm_admin_language_recent_v1`**、**`pm_admin_genre_recent_v1`**（`id → 时间戳`）。
- 勾选与 **保存元数据** 后通过 **`recordMetadataLanguageGenreRecent`** 更新最近使用。
- **`loadLanguages` / `loadGenres`**：当存在 **`state.editingSongId`**（正在编辑歌曲）时，重载列表后通过 **`getSelectedLanguageIds` / `getSelectedGenreIds`** 再渲染多选，避免刷新把抽屉内已选清空。

### 主要文件

- `app/static/admin.js`：`loadIdRecentMap` / `touchLanguageRecent` / `touchGenreRecent` / `sortByRecentName`、`renderLanguageMultiSelect` / `renderGenreMultiSelect` 重写、`saveSingleMetadata` 中写入 `genreIds` 并调用 `recordMetadataLanguageGenreRecent`。
