# 音乐扫描上传与入库

## 背景
ProjectSoulKing 当前已在代码与已生效 OpenSpec 中实现 `music-ingestion` 能力。为避免需求状态只存在于对话或规格结果中，本需求将该能力回填到 `issues/requirements`，作为可审计的历史需求档案。

## 目标用户
- 个人音乐库维护者
- 管理员
- 已登录普通用户（适用于面向前台或账号自助的能力）

## 用户价值
定义「音乐入库」能力：从本地目录递归扫描符合格式的音频文件，或通过上传接口接收多个音频文件，将其写入对象存储并在曲库中建立或关联歌曲与专辑记录；同时提供一次操作范围内的进度与跳过说明查询能力。本规范仅描述当前已实现行为。

## 范围 In
- 覆盖 `music-ingestion` 已生效规格中的 11 个 Requirement。
- 以当前代码、OpenSpec 与产品文档描述的已实现行为为准。
- 保留规格中的 Notes 与 Known Gaps 作为后续演进输入。

## 范围 Out
- 不在本需求中新增接口、数据结构、权限边界或 UI 行为。
- 不直接修改 `openspec/specs/`，仅引用其作为已生效事实源。
- 不承诺修复 Known Gaps；后续若处理需另建 REQ/BUG 与 OpenSpec Change。

## Notes
- 默认导入根路径由应用配置提供；请求体中的目录字段可覆盖该默认值。
- 允许的后缀集合由应用侧固定配置；扩展名过滤行为以当前实现为准。
- 上传入口在逐文件处理间隙对异步调度短暂让步，不改变「单次目录扫描请求同步完成」的结论。
- 对外目录扫描接口在调用扫描逻辑前校验路径，故扫描任务处于「已创建但根路径立刻不可用」的失败分支在正常 HTTP 使用中极少出现。

## Known Gaps
以下行为未以强制性语句写入正文，或仅部分覆盖：

- **进度隔离**：多个并发扫描或上传请求共用同一进程内进度快照，可能互相覆盖。
- **扫描任务结束时间**：持久任务记录可能包含「结束时间」类字段，完成路径未必写入。
- **候选文件总数与已扫描数**：响应中的总数来自扫描前枚举，任务统计来自遍历；二者在目录内容变化时未必相等。
- **前端交互**：管理界面如何触发扫描与上传、是否轮询进度，需对照静态前端单独描述。
- **对象存储删除失败**：清理已上传对象时删除失败不会阻止流程返回跳过或错误说明。
