# single-tenant-trust-model Specification

## Purpose

定义「单租户、全信任」安全与归属模型：本系统在应用层**不对 HTTP 请求做身份鉴别或授权区分**；同一部署实例使用**单一数据库连接**承载全部业务数据，且不引入租户标识维度；可选的外部服务密钥仅在服务端用于出站调用。本规范描述当前实现下的信任边界；传输加密、网络隔离、反向代理鉴权等若存在则属于部署环境，不在此承诺。

## Requirements

### Requirement: 入站 HTTP 无应用层身份鉴别

服务端在处理 HTTP API 请求时，**未**将「调用方身份令牌或会话」作为路由前置条件；不因缺少登录态、应用级 API 密钥或同类凭证而单独拒绝请求。**仍会**因载荷校验失败、资源不存在、业务规则不满足等非身份原因返回错误。

#### Scenario: 无凭证访问数据接口

- **GIVEN** 客户端未附应用自定义的身份凭证（仅常规 HTTP 请求）
- **WHEN** 客户端请求读取类业务接口
- **THEN** 不因「未登录」类原因单独拒绝（若资源存在则按业务返回）

#### Scenario: 无凭证访问写操作接口

- **GIVEN** 客户端未附应用自定义的身份凭证
- **WHEN** 客户端请求创建、更新或删除类业务接口且载荷通过校验
- **THEN** 不因「未登录」类原因单独拒绝

### Requirement: 单一数据存储连接

运行时通过**一项**数据库连接配置指向**一个**数据库实例；应用通过该连接访问全部持久化业务数据。

#### Scenario: 配置指向单库

- **GIVEN** 部署已设置数据库连接配置
- **WHEN** 应用访问曲目、歌单等业务数据
- **THEN** 数据均来自该配置所指的同一数据库实例语义（非多套并行库切换）

### Requirement: 无应用层多租户分区语义

业务数据模型与查询路径**不**依赖「租户标识、组织标识」等字段做强制隔离；不提供在同一进程内按租户切分数据集的机制。

#### Scenario: 数据访问不带租户维度

- **GIVEN** 库中存在业务记录
- **WHEN** 服务端列出或读写该类记录
- **THEN** 不因租户 id 缺失而拒绝（隔离维度不在模型约定中）

### Requirement: 出站第三方密钥仅服务端使用

若配置了外部工作流等第三方服务的访问地址与密钥，服务端仅在**出站**调用时使用配置中的密钥组装授权信息；该密钥**不作为**客户端可调用的入站鉴别依据。

#### Scenario: 密钥取值不出现在静态资源正文中

- **GIVEN** 部署在服务端配置了外部工作流密钥（密钥取值仅存于服务端配置）
- **WHEN** 客户端获取仓库随附的前台或后台入口 HTML 及与之关联的静态脚本
- **THEN** 上述静态文件内容中不包含该密钥的明文取值

## Notes

- 产品文档中说明本 MVP 为单用户场景且不包含认证能力；与上述「入站无身份鉴别」一致。
- 服务端源码中**未**注册常见的跨域资源共享中间件；浏览器跨站访问时的限制主要来自浏览器同源策略，非应用内统一策略字段。
- 「管理」命名空间下的接口与前台接口在**同一进程与同一信任平面**上暴露；是否限制访问取决于网络可达性与部署方式。
- 界面文案或脚本中可出现**环境变量名称**等提示语（例如提示需在服务端配置某变量），与「密钥取值写入前端」不是同一回事。
- 无身份鉴别**不表示**请求必定成功：请求体验证错误、业务层未找到资源等仍会返回相应错误状态。

## Known Gaps

- **部署侧控制**：反向代理基本认证、IP 限制、TLS 终止等若启用，属运维与网关配置，本仓库应用代码无法逐项断言。
- **多人同时使用**：应用层不区分自然人身份；若服务监听对外网络，技术上可被多名客户端共用同一数据，与产品「单用户」表述的边界在运维层面。
- **审计与追责**：未见按请求记录操作者身份的专用机制；事后归因依赖外部日志或部署扩展。
