## Why

前台音乐库页面仍保留未实现的 Tab（全部歌曲 / 我喜欢的 / 最近播放）、占位「智能排序」按钮，以及分散在顶栏与内容区的搜索/筛选布局；列表字段也与后台歌曲管理不一致，信息密度与可筛选维度不对齐。用户浏览曲库时需要与后台一致、可直接使用的筛选与列展示，减少认知负担并提升查找效率。

## What Changes

- **移除曲库 Tab 栏**：删除「全部歌曲 / 我喜欢的 / 最近播放」Tab 及 `libraryTab` 相关切换逻辑；音乐库默认展示全部可访问歌曲。
- **移除智能排序**：删除「智能排序」按钮及其占位 toast 逻辑。
- **搜索 + 筛选工具栏对齐后台**：将搜索框从顶栏移至音乐库内容区工具栏，与「更多筛选」「重置」同一行排列；展开面板布局与后台歌曲管理一致（原唱、作词、作曲、标签、格式、语言多选筛选）；顶栏在音乐库视图下不再显示全局搜索（保留歌单等其它视图的搜索行为不变）。
- **列表字段扩展**：表格列调整为：#、歌曲、原唱、作词、作曲、专辑、语言、标签、格式、时长、发行日期、操作；保留序号列 `#`（随分页偏移递增）；歌曲列保留封面占位/标题/播放态指示，操作列保留试听、收藏、加入歌单、下载等前台操作。
- **筛选 API 对齐**：前台 `loadSongs` 查询参数扩展为支持原唱、作词、作曲筛选（与后台 `/songs` 列表接口已有参数一致），并在筛选变更时刷新列表。
- 递增 `index.html` / `frontend.js` / `studio.css` 静态资源 `?v=` 缓存版本。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `web-static-client-shells`：前台音乐库内容区 DOM 结构、工具栏/筛选面板布局、表格列定义及 Tab/智能排序移除的验收场景。

## Impact

- **前端**：`app/static/index.html`（音乐库区块 DOM、顶栏搜索可见性）、`app/static/studio.css`（工具栏一行布局、筛选面板、表格列宽）、`app/static/frontend.js`（移除 Tab/智能排序、工具栏筛选逻辑、列渲染、查询参数）。
- **后端 / API**：无变更（复用现有 `/songs` 列表筛选参数与歌曲响应字段）。
- **行为说明**：「我喜欢的」「最近播放」不在本变更范围，后续单独变更接入；顶栏 ⌘K 快捷键若仍绑定原搜索框需迁移至内容区搜索框或按视图切换绑定目标。
