## MODIFIED Requirements

### Requirement: 后台歌曲管理页快速筛选选项来源

后台壳内歌曲管理页「更多筛选」中，原唱、作词、作曲、标签、语言、风格六个维度的下拉可选项 MUST 取自参考数据管理列表，而非从当前曲库歌曲字段推导；格式维度不受本要求约束。

各维度选项来源 SHALL 为：

| 维度 | 数据来源 | 过滤规则 |
|------|----------|----------|
| 原唱 | 艺人管理（`/people`） | `types` 包含「歌手」 |
| 作词 | 艺人管理 | `types` 包含「作词」 |
| 作曲 | 艺人管理 | `types` 包含「作曲」 |
| 标签 | 标签管理（`/tags`） | 全部标签名称 |
| 语言 | 语言管理（`/languages`） | 全部语言名称 |
| 风格 | 风格管理（`/genres`） | 全部风格名称 |

选项值 SHALL 为对应条目的 **名称** 字符串（与列表过滤时使用的歌曲元数据字段一致），并按名称升序排列。

风格筛选在 UI 上 MUST 位于语言筛选之后。用户选择风格后，客户端 MUST 将所选名称映射为 `genre_ids` 并随 `GET /songs` 提交；同维度多选为 OR，跨维度 AND。

#### Scenario: 原唱选项来自歌手类型艺人

- **GIVEN** 艺人管理中存在名称「甲」且 `types` 包含「歌手」，存在名称「乙」且 `types` 仅包含「作词」
- **WHEN** 用户打开歌曲管理页「更多筛选」中的原唱下拉
- **THEN** 可选项包含「甲」
- **AND** 可选项不包含「乙」

#### Scenario: 作词与作曲选项按类型区分

- **GIVEN** 艺人「丙」的 `types` 为「作词」，艺人「丁」的 `types` 为「作曲」
- **WHEN** 用户分别打开作词、作曲筛选下拉
- **THEN** 作词可选项包含「丙」且不包含「丁」（除非「丁」亦为作词类型）
- **AND** 作曲可选项包含「丁」且不包含「丙」（除非「丙」亦为作曲类型）

#### Scenario: 标签、语言与风格选项来自管理列表

- **GIVEN** 标签管理中存在「流行」，语言管理中存在「国语」，风格管理中存在「摇滚」，且当前曲库中没有任何歌曲带有该标签、语言或风格
- **WHEN** 用户打开标签、语言或风格筛选下拉
- **THEN** 可选项仍分别包含「流行」「国语」「摇滚」

#### Scenario: 风格筛选位于语言之后

- **GIVEN** 用户展开歌曲管理页「更多筛选」面板
- **WHEN** 用户从左至右查看筛选控件顺序
- **THEN** 「风格」控件紧跟在「语言」控件之后

#### Scenario: 参考数据变更后刷新筛选项

- **GIVEN** 用户已在歌曲管理页
- **WHEN** 客户端完成艺人、标签、语言或风格管理数据的重新加载（如新增、编辑、删除后触发的 `loadPeople` / `loadTags` / `loadLanguages` / `loadGenres`）
- **THEN** 对应维度的下拉选项列表更新为与管理数据一致的集合
- **AND** 仍保留当前仍存在于新选项列表中的已选值

### Requirement: 后台歌曲管理页列表表格列与顺序

后台壳内歌曲管理页主表格 SHALL 按下列顺序展示列（不含行首勾选列）：歌曲、原唱、作词、作曲、专辑、语言、风格、影视剧、标签、格式、时长、发行日期、元数据、创建时间、更新时间、操作。

各列展示规则 SHALL 为：

| 列 | 数据来源 / 展示 |
|----|-----------------|
| 歌曲 | 歌曲标题；无副文案时长（时长独立列） |
| 原唱 | `lead_artist` 或等价主唱展示串 |
| 作词 | 词作者名字列表，以「、」或「 / 」连接 |
| 作曲 | 曲作者名字列表，以「、」或「 / 」连接 |
| 专辑 | 专辑名 |
| 语言 | 语言展示名 |
| 风格 | `genre` 展示名；无值时显示「—」 |
| 影视剧 | `film_tv` 文本；无值时显示「—」 |
| 标签 | 标签名列表 |
| 格式 | 代表性音频格式标签 |
| 时长 | `duration_ms` 格式化为 `mm:ss` |
| 发行日期 | `release_date` 原文或格式化展示 |
| 元数据 | 元数据完成度进度条与百分比 |
| 创建时间 | `created_at` 本地化展示 |
| 更新时间 | `updated_at` 本地化展示 |
| 操作 | 见「后台歌曲管理页列表操作按钮」 |

表格 MUST NOT 包含「年份」「封面」「状态」「歌词」列。

支持排序的列（若实现表头排序）SHALL 与上述字段对应，且排序请求参数与曲库列表 API 的 `sort_by` 一致；「影视剧」列排序参数 MUST 为 `film_tv`；「风格」列排序参数 MUST 为 `genre`。

#### Scenario: 列顺序与必填字段展示

- **GIVEN** 歌曲管理页已加载且列表至少一条记录
- **WHEN** 用户查看表头
- **THEN** 表头从左至右（勾选列之后）依次为歌曲、原唱、作词、作曲、专辑、语言、风格、影视剧、标签、格式、时长、发行日期、元数据、创建时间、更新时间、操作
- **AND** 不出现年份、封面、状态、歌词列

#### Scenario: 空字段占位

- **GIVEN** 某歌曲缺少作词或作曲关联，或 `film_tv` 为空，或 `genre` 为空
- **WHEN** 渲染该行
- **THEN** 对应单元格显示「—」或等价占位

#### Scenario: 影视剧列展示与排序

- **GIVEN** 某歌曲 API 响应 `film_tv` 为「琅琊榜」
- **WHEN** 该歌曲出现在后台列表中
- **THEN** 影视剧列单元格展示「琅琊榜」
- **WHEN** 用户点击影视剧列表头排序
- **THEN** 列表请求携带 `sort_by=film_tv` 及当前升降序参数

#### Scenario: 风格列展示与排序

- **GIVEN** 某歌曲 API 响应 `genre` 为「流行」
- **WHEN** 该歌曲出现在后台列表中
- **THEN** 风格列单元格展示「流行」
- **WHEN** 用户点击风格列表头排序
- **THEN** 列表请求携带 `sort_by=genre` 及当前升降序参数

### Requirement: 前台壳音乐库内容区布局与筛选

前台壳内「音乐库」主内容区（`#songBrowseSection`）SHALL 展示单一歌曲列表视图，MUST NOT 包含「全部歌曲 / 我喜欢的 / 最近播放」Tab 栏或等价视图切换控件，MUST NOT 包含「智能排序」或等价占位排序入口。

内容区 SHALL 提供与后台歌曲管理页一致的工具栏布局：同一行内包含搜索框、「更多筛选」按钮与「重置」按钮（有活跃筛选条件时显示重置）。搜索框 placeholder 与清空按钮行为 SHALL 与后台歌曲管理搜索框等价（支持关键字搜索歌曲/艺人/专辑/标签等）。

用户点击「更多筛选」时 SHALL 展开/收起筛选面板；面板内 SHALL 为原唱、作词、作曲、标签、格式、语言、风格七个维度提供可搜索的多选下拉，布局与交互模式对齐后台 `adm-filters-panel`；「风格」MUST 位于「语言」之后。筛选条件 MUST 通过曲库列表 API 查询参数提交并在服务端生效（风格维度以 `genre_ids` 提交）。

在音乐库视图激活时，整个顶栏区域（`.studio-top-header`）SHALL 隐藏，避免空白占空间及与内容区搜索重复；用户通过键盘快捷键（如 ⌘K / Ctrl+K）时 SHALL 聚焦内容区搜索框（`#libraryKeywordInput`）。

#### Scenario: 音乐库无 Tab 与智能排序

- **GIVEN** 用户打开前台壳并进入音乐库视图
- **WHEN** 用户查看音乐库内容区标题下方区域
- **THEN** 不存在「全部歌曲」「我喜欢的」「最近播放」Tab 控件
- **AND** 不存在「智能排序」按钮

#### Scenario: 搜索与更多筛选同一行

- **GIVEN** 用户打开前台壳并进入音乐库视图
- **WHEN** 用户查看筛选工具栏
- **THEN** 搜索输入框与「更多筛选」按钮位于同一工具栏行内
- **AND** 布局模式与后台歌曲管理页工具栏一致（搜索区可伸展，筛选按钮靠行内排列）

#### Scenario: 展开七维筛选面板

- **GIVEN** 用户处于音乐库视图且筛选面板未展开
- **WHEN** 用户点击「更多筛选」
- **THEN** 展开面板显示原唱、作词、作曲、标签、格式、语言、风格七个多选筛选控件
- **AND** 「风格」控件位于「语言」之后
- **AND** 用户选择条件后列表按服务端过滤结果刷新

#### Scenario: 音乐库视图隐藏整个顶栏

- **GIVEN** 用户处于音乐库视图
- **WHEN** 用户查看主内容区上方
- **THEN** `.studio-top-header` 不可见且不占用垂直布局空间
- **AND** 内容区工具栏搜索框可用

#### Scenario: 重置筛选

- **GIVEN** 用户已设置至少一项筛选条件
- **WHEN** 用户点击「重置」
- **THEN** 所有筛选控件清空
- **AND** 列表恢复为无筛选条件下的结果

### Requirement: 前台壳音乐库歌曲列表列定义

前台壳音乐库歌曲表格 SHALL 包含以下列（从左至右）：**#**、**歌曲**、**原唱**、**作词**、**作曲**、**专辑**、**语言**、**风格**、**影视剧**、**标签**、**格式**、**时长**、**发行日期**、**操作**。

序号列（`#`）SHALL 展示当前页内的行序号（随分页偏移递增，如第 2 页每页 20 条时首行显示 21）。歌曲列 SHALL 仅展示曲目标题及播放态指示（若当前正在播放）；MUST NOT 包含封面图、音符图标、`sk-thumb` 或任何等价歌曲图标/缩略图占位。

操作列 MUST 默认仅展示「更多」触发按钮（文案或图标为「⋯」或等价，含 `aria-label`）；试听、加入歌单、下载 MUST 置于该按钮展开的下拉菜单项中，且 MUST 保留既有权限与禁用逻辑（无网页可试听音频时试听/加入歌单为 disabled 并展示说明）。操作列 MUST NOT 在默认态并排展示多个独立图标按钮；MUST NOT 包含收藏按钮或等价占位控件。

列数据 SHALL 映射歌曲 API 响应字段：`lead_artist`、`lyricists`、`composers`、`album`、`language`、`genre`、`film_tv`、`tags`、`formats`/`file_format`、`duration_ms`、`release_date`。

#### Scenario: 列表展示完整列

- **GIVEN** 用户打开音乐库且曲库有至少一首含完整元数据的歌曲
- **WHEN** 列表渲染完成
- **THEN** 表头依次为 #、歌曲、原唱、作词、作曲、专辑、语言、风格、影视剧、标签、格式、时长、发行日期、操作
- **AND** 首列 `#` 展示当前页行序号

#### Scenario: 歌曲列无图标占位

- **GIVEN** 用户查看音乐库列表任意数据行
- **WHEN** 用户查看「歌曲」列单元格
- **THEN** 仅可见曲目标题文本及（若正在播放）播放态指示
- **AND** 不存在封面缩略图、音符图标或其它歌曲图标元素

#### Scenario: 元数据字段正确展示

- **GIVEN** 某歌曲 API 响应含 `lead_artist`、`lyricists`、`composers`、`genre`、`film_tv`、`release_date`
- **WHEN** 该歌曲出现在音乐库列表中
- **THEN** 对应单元格展示正确文本（作词/作曲为多值时以可读形式合并展示；`genre` 或 `film_tv` 为空时显示「—」）
- **AND** 发行日期以日期格式或占位符「—」展示

#### Scenario: 操作列默认仅展示更多按钮

- **GIVEN** 用户查看音乐库列表任意数据行的操作列
- **WHEN** 用户未展开该行操作菜单
- **THEN** 操作列仅可见「更多」类触发控件
- **AND** 试听、加入歌单、下载不在默认态并排展示

## ADDED Requirements

### Requirement: 后台歌曲管理页编辑抽屉风格字段

编辑抽屉主表单 MUST 在可见区域提供「风格」字段，交互 MUST 与「语言」字段一致：使用 `multi-select` 组件，支持从风格管理列表（`/genres`）加载选项、关键字模糊搜索、多选勾选/取消、搜索框内输入无完全匹配项时创建风格（`POST /genres`）并自动选中、触发器以 chip 展示已选项。该字段 MUST NOT 仅存在于 `adm-hidden-filters` 或其它默认隐藏区。字段在表单中的位置 MUST 紧邻「语言」字段（同一网格行或相邻表单项，语言在前、风格在后）。保存元数据时 MUST 提交所选 `genre_ids`（或与现有保存 API 等价的风格 id 列表）。

#### Scenario: 打开编辑抽屉可见风格字段

- **GIVEN** 用户打开某首歌曲的编辑抽屉
- **WHEN** 抽屉元数据表单渲染完成
- **THEN** 用户可在主表单可见区域看到标签为「风格」的多选控件
- **AND** 该控件与「语言」多选控件均不在 `adm-hidden-filters` 内

#### Scenario: 风格模糊搜索与新建

- **GIVEN** 编辑抽屉已打开且风格管理中存在名称包含「流」的风格
- **WHEN** 用户在风格多选搜索框输入「流」
- **THEN** 下拉列表显示名称模糊匹配的风格选项
- **WHEN** 用户输入不存在的风格名并选择创建
- **THEN** 系统创建该风格并加入当前歌曲已选风格集合

#### Scenario: 保存后风格回显

- **GIVEN** 用户为某曲选择了风格「流行」并保存
- **WHEN** 用户再次打开该曲编辑抽屉
- **THEN** 风格多选触发器展示「流行」（或等价 chip）
