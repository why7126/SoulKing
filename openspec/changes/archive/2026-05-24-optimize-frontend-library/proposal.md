## Why

前台音乐库页面在 Studio 改版后存在多处 UX 问题：顶栏空白占空间、分页未对齐后台服务端模式导致翻页不可用或信息缺失、操作列与播放器残留未实现的占位控件、横向滚动时序号与歌曲列无法固定。这些问题影响日常浏览曲库的效率与界面整洁度，应在收藏、音质等能力上线前集中修复。

## What Changes

- **顶栏**：音乐库视图下隐藏整个 `studio-top-header`（不再仅隐藏搜索框），释放约 56px 垂直空间。
- **分页**：前台音乐库列表对齐后台 admin 的服务端分页（`offset` + `limit`）；翻页、切换每页条数时重新请求 API；保留 API 返回的 `total`，不在 `renderSongList` 中用 `songs.length` 覆盖；页脚补充「第 X / Y 页」及「显示 A–B，共 N 首」文案。
- **操作列**：行内操作按钮图标垂直/水平居中；移除列表操作列中的收藏按钮及相关 toast 占位逻辑。
- **播放模式**：底部播放器 transport 区改用带标签的下拉或 popover（方案 B）展示四种播放模式，替代仅靠 emoji 循环切换；与随机按钮的交互关系在设计阶段明确并简化重复入口。
- **占位控件隐藏**：隐藏播放器右侧「调」（音质）按钮；隐藏播放器左侧收藏按钮、详情面板收藏按钮；词/全屏等其它未实现辅助按钮保持现状或一并隐藏（仅「调」与三处收藏为本次明确范围）。
- **冻结列**：音乐库表格横向滚动时，**#** 与 **歌曲** 两列 sticky 固定，行为对齐后台歌曲管理页的冻结列体验。

## Capabilities

### New Capabilities

（无 — 本次为既有前台壳能力的 UX 修正，不引入独立新业务域。）

### Modified Capabilities

- `web-static-client-shells`：扩展/修正前台音乐库布局（顶栏显隐）、服务端分页与页脚信息、操作列与收藏占位移除、播放模式控件、表格冻结列等壳层行为要求。

## Impact

- **前端静态资源**：`app/static/index.html`、`app/static/frontend.js`、`app/static/studio.css`（可能少量 `styles.css` 复用 sticky 变量）。
- **后端 API**：复用现有 `GET /songs` 的 `offset`/`limit`/`total` 契约，无接口变更。
- **不受影响**：后台 admin 分页实现、歌单详情页、侧栏收起/展开（已有独立规范）。
