# song-catalog-and-metadata Specification

## Purpose

定义「曲库与元数据」能力：浏览与筛选歌曲列表、读取详情、编辑歌曲及其关联元数据（艺人角色、专辑、标签、语言、风格等）、批量修改部分字段，以及删除歌曲记录；并在适用场景下，在保存后为歌曲关联的音频对象调整存储路径。本规范仅描述当前已实现行为。

## Requirements

### Requirement: 歌曲列表与多维筛选

客户端可请求歌曲列表，并可选传入关键词、主档艺人名、专辑名、语言名、风格标识、标签标识、原唱/合唱/词/曲作者名字、音频格式与码率及采样率等条件。服务端先基于持久数据做部分条件的查询收窄，再在请求处理过程中对其余条件逐条过滤并组装列表项。列表接口还支持排序字段、升降序、偏移与条数上限。

#### Scenario: 关键词过滤范围

- **GIVEN** 请求携带关键词参数
- **WHEN** 服务端筛选候选歌曲
- **THEN** 关键词在歌曲标题、原唱展示串、合唱展示串、专辑名、影视相关字段、词作者与曲作者名字拼接串等字段上做包含匹配（不区分大小写）
- **AND** 标签名称全文不参与该关键词匹配
- **AND** 列表项中用于展示的合并艺人长串（若与上述拆分字段合成方式不同）不参与该关键词匹配

#### Scenario: 主档艺人名与专辑名筛选

- **GIVEN** 请求携带主档艺人名列表或专辑名列表
- **WHEN** 构建筛选结果
- **THEN** 主档艺人条件作用于歌曲记录上关联的主档艺人名称；专辑条件作用于歌曲记录上关联的专辑名称

#### Scenario: 语言筛选

- **GIVEN** 请求携带语言名称列表，且至少一名称能在语言字典中解析到记录
- **WHEN** 筛选歌曲
- **THEN** 命中歌曲满足「单行首选语言」或「多语言关联」任一匹配所选语言

#### Scenario: 语言名称均无法解析时列表为空

- **GIVEN** 请求携带语言名称列表，且所有名称均无法在语言字典中解析到记录
- **WHEN** 请求列表
- **THEN** 返回空列表

#### Scenario: 风格筛选

- **GIVEN** 请求携带若干风格标识
- **WHEN** 筛选歌曲
- **THEN** 命中歌曲满足「单行首选风格」或「多风格关联」任一匹配所选风格

#### Scenario: 标签筛选仅在有有效解析时生效

- **GIVEN** 请求携带若干标签标识，且至少其一能解析到标签记录
- **WHEN** 筛选歌曲
- **THEN** 仅保留歌曲当前标签与所选标签集合存在交集的歌曲

#### Scenario: 标签标识全部无效时标签条件不生效

- **GIVEN** 请求携带若干标签标识，且无一能解析到标签记录
- **WHEN** 筛选歌曲
- **THEN** 不因标签条件排除歌曲（其它筛选条件仍适用）

#### Scenario: 按角色名字筛选

- **GIVEN** 请求携带原唱、合唱、词作者或曲作者名字列表之一
- **WHEN** 筛选歌曲
- **THEN** 仅保留在该角色当前名字列表中，至少命中查询参数中某一完整名字一项的歌曲

### Requirement: 列表中的音频文件相关展示与筛选

当歌曲下存在音频文件时，列表项在通过筛选后，会依据应用配置的格式优先级与码率等规则选取一条代表性音频用于展示格式、大小、码率等字段；并可按格式、码率、采样率进一步收窄候选文件。

#### Scenario: 带文件相关筛选时无音频的歌曲不出现

- **GIVEN** 某歌曲下没有任何音频文件记录
- **WHEN** 请求列表且带有格式、或多种格式、或码率、或采样率中任一类筛选条件
- **THEN** 该歌曲不出现在结果中

#### Scenario: 无文件相关筛选时可出现仅元数据的歌曲

- **GIVEN** 某歌曲下没有任何音频文件记录
- **WHEN** 请求列表且不带有格式、多种格式、码率、采样率筛选
- **THEN** 该歌曲仍可出现于结果中（若通过其它筛选）

### Requirement: 歌曲列表分页响应形态

`GET /songs` 成功响应 SHALL 为 JSON 对象，包含：

- `items`：当前页的 `SongOut` 数组（与分页、筛选、排序参数一致）；
- `total`：满足当前请求中所有筛选与关键词条件后的歌曲总条数（用于分页，可大于 `items.length`）；
- `library_total`：曲库中歌曲记录总数（忽略本次请求的筛选参数）。

#### Scenario: 默认分页响应结构

- **GIVEN** 曲库中存在歌曲
- **WHEN** 客户端请求 `GET /songs` 并指定 `offset=0`、`limit=20`
- **THEN** 响应体为对象且包含 `items`、`total`、`library_total`
- **AND** `items` 长度不超过 20
- **AND** `total` 为通过筛选后的全集条数
- **AND** `library_total` 等于库内全部歌曲行数

#### Scenario: 筛选后 total 与 library_total 区分

- **GIVEN** 全库 100 首，其中 10 首满足请求中的原唱筛选
- **WHEN** 客户端携带该原唱筛选请求列表
- **THEN** `total` 为 10
- **AND** `library_total` 为 100

#### Scenario: 无匹配时 items 为空且 total 为零

- **GIVEN** 筛选条件无歌曲命中
- **WHEN** 客户端请求列表
- **THEN** `items` 为空数组
- **AND** `total` 为 0
- **AND** `library_total` 仍为全库条数

### Requirement: 列表排序与分页

服务端在内存中对已通过筛选的列表项按所选字段排序后，再按偏移与条数将结果放入响应的 `items`；同时将筛选后全集条数写入 `total`，将库内歌曲总数写入 `library_total`。

#### Scenario: 默认排序与分页

- **GIVEN** 客户端使用默认排序键与排序方向，并指定偏移与条数
- **WHEN** 请求列表
- **THEN** `items` 顺序与分页切片与请求参数一致
- **AND** `total` 反映筛选后全部条数而非仅当前页条数

### Requirement: 管理端筛选选项

客户端可请求一项聚合接口，用于填充筛选 UI：包括库中出现的音频格式、码率与采样率，标签与语言与风格字典项，以及从现有歌曲汇总得到的原唱与合唱等名字集合等。

#### Scenario: 返回聚合选项

- **GIVEN** 曲库与字典中存在数据
- **WHEN** 客户端请求筛选选项接口
- **THEN** 响应中包含可用于筛选与展示的聚合字段

### Requirement: 歌曲详情

客户端可按歌曲标识请求详情。资源不存在时返回未找到错误。详情中包含标题、展示用艺人串、原唱与合唱及词曲角色、专辑、时长、标签与语言及风格的展示名与多选标识、关联的音频文件条目及每条的基本属性。

#### Scenario: 详情存在与不存在

- **GIVEN** 有效的歌曲标识
- **WHEN** 请求详情
- **THEN** 返回包含上述字段的详情体

- **GIVEN** 不存在的歌曲标识
- **WHEN** 请求详情
- **THEN** 返回未找到错误

### Requirement: 更新歌曲元数据

客户端可提交部分字段更新一首歌：标题、专辑名、时长、标签标识集合、语言（单行或多选）、风格（单行或多选）、原唱与合唱艺人标识集合、词作者与曲作者标识集合、发行相关文本与影视相关文本等。当更新请求修改了歌曲标题且与保存前标题（去首尾空白后）不同时，服务端 MUST 在调整对象存储路径之前，将该歌曲下全部关联音频文件与歌词文件的展示用原始文件名（`original_filename`）统一更新为：主文件名为经路径安全处理后的新标题、扩展名与该文件既有格式一致（歌词为 `.lrc`）。随后在持久化提交前，服务端根据当前已写入的元数据尝试调整该歌曲关联文件在对象存储中的路径。

#### Scenario: 标题为空被拒绝

- **GIVEN** 更新请求包含标题字段且将其设为空字符串或仅空白
- **WHEN** 提交更新
- **THEN** 返回表示请求无效的错误

#### Scenario: 时长为负被拒绝

- **GIVEN** 更新请求将时长设为小于零的数
- **WHEN** 提交更新
- **THEN** 返回表示请求无效的错误

#### Scenario: 语言或风格标识不存在被拒绝

- **GIVEN** 更新请求通过单行或多选路径引用语言或风格标识，且其中某一标识在字典中不存在
- **WHEN** 提交更新
- **THEN** 返回未找到类错误

#### Scenario: 风格单行清空

- **GIVEN** 更新请求通过单行风格路径传入表示「清空」的约定取值
- **WHEN** 提交更新且校验通过
- **THEN** 歌曲的多风格关联被清空

#### Scenario: 专辑非空则关联或创建专辑

- **GIVEN** 更新请求包含专辑字段且去空白后为非空字符串
- **WHEN** 提交更新
- **THEN** 在库中查找或创建对应专辑并关联到歌曲（与当前主档艺人取值一致前提下）

#### Scenario: 专辑为空则解除专辑关联

- **GIVEN** 更新请求包含专辑字段且去空白后为空
- **WHEN** 提交更新
- **THEN** 歌曲不再关联专辑

#### Scenario: 原唱或合唱列表变更时同步主档与合唱的外键列

- **GIVEN** 更新请求在载荷中显式包含原唱或合唱艺人标识列表字段之一（含可解析为空列表）
- **WHEN** 提交更新并写入关联表
- **THEN** 歌曲记录上的主档艺人外键取原唱列表首项（若无则为空），合唱外键取合唱列表首项（若无则为空）

#### Scenario: 仅存在于库中的艺人标识会被写入角色关联

- **GIVEN** 更新请求包含若干艺人标识，其中部分在艺人库中不存在
- **WHEN** 写入原唱、合唱、词曲角色关联
- **THEN** 仅对已存在的艺人标识建立关联行

#### Scenario: 保存前尝试调整存储路径

- **GIVEN** 更新已通过校验并即将提交持久化
- **WHEN** 提交事务之前
- **THEN** 服务端根据当前元数据尝试搬迁该歌曲下各关联文件对象的存储路径（单对象搬迁失败时的行为见 Known Gaps）

#### Scenario: 未在载荷中提供原唱或合唱列表时不重算主档外键

- **GIVEN** 更新请求未在载荷中携带原唱艺人标识列表字段，也未携带合唱艺人标识列表字段
- **WHEN** 提交更新
- **THEN** 不因本请求单独重算主档或合唱外键列（其它字段仍可按载荷更新）

#### Scenario: 标题变更时同步全部关联文件展示名

- **GIVEN** 某歌曲有关联的音频文件（一种或多种格式）及可选的歌词文件
- **AND** 更新请求将标题设为去空白后与当前标题不同的非空字符串
- **WHEN** 提交更新并成功持久化
- **THEN** 每条音频文件的 `original_filename` 为 `{安全化新标题}.{该文件格式扩展名}`
- **AND** 若存在歌词文件，其 `original_filename` 为 `{安全化新标题}.lrc`
- **AND** 随后执行的对象存储路径调整使用更新后的展示名作为路径中的文件名片段

#### Scenario: 标题未变更时不强制重命名关联文件

- **GIVEN** 更新请求包含标题字段且去空白后与当前歌曲标题相同
- **WHEN** 提交更新
- **THEN** 服务端不因标题单独触发将全部关联文件展示名重置为新标题 stem 的逻辑
- **AND** 若其它元数据变更需要，仍可执行存储路径调整

### Requirement: 批量更新歌曲元数据

客户端可提交一组歌曲标识，以及可选的主档艺人名字、专辑名字、标签标识集合；对查询到的每条歌曲应用相同变更。主档艺人名字非空时在库中查找或创建艺人并写入歌曲；专辑名字非空时在库中查找或创建专辑并写入歌曲；可同时更新标签关联。在持久化提交前对每条被查询到的歌曲尝试调整存储路径。

#### Scenario: 歌曲标识列表为空被拒绝

- **GIVEN** 批量请求中歌曲标识列表为空
- **WHEN** 提交批量更新
- **THEN** 返回表示请求无效的错误

#### Scenario: 部分标识不存在时不报错

- **GIVEN** 批量请求包含若干歌曲标识，其中部分在库中不存在
- **WHEN** 提交批量更新
- **THEN** 仅更新能查到的歌曲，不因缺失标识单独返回错误

#### Scenario: 批量保存前尝试调整存储路径

- **GIVEN** 批量更新已写入待提交的数据库变更
- **WHEN** 单次批量请求在提交事务之前
- **THEN** 对被更新的歌曲依次尝试搬迁关联音频的存储路径

### Requirement: 删除歌曲记录

客户端可请求删除一首歌曲。若歌曲不存在则返回未找到。删除流程会在持久存储中移除与该歌曲相关的歌单条目、标签关联、风格关联、语言关联及音频文件记录，然后移除歌曲记录本身。

#### Scenario: 删除存在与不存在

- **GIVEN** 有效的歌曲标识
- **WHEN** 请求删除
- **THEN** 返回成功指示

- **GIVEN** 不存在的歌曲标识
- **WHEN** 请求删除
- **THEN** 返回未找到错误

## Notes

- 列表查询里「主档艺人名」筛选依据歌曲记录上的主档艺人外键所对应的艺人名称，与「原唱名字」筛选（基于原唱角色关联汇总）是两条不同路径。
- 排序在筛选结果集上于服务端内存中完成；默认排序键为创建时间、默认降序；若传入无法识别的排序键，实现回退到按创建时间排序。
- 更新请求中：词曲角色字段若出现在载荷中则按载荷重写（可清空）；若未出现且当前仍有词曲关联，则保持现有词曲关联写入。
- 更新请求中标签标识列表仅会为库中已存在的标签建立关联，无效标识被静默忽略，不单独报错。
- 批量更新可为多条歌曲创建新的艺人或专辑记录（当对应名字字段非空时）。

## Known Gaps

以下为未以强制性语句写入正文、或依赖部署层的行为：

- **对象存储中的音频对象**：删除歌曲时，路由实现移除音频文件的数据库记录，但未在同一请求内删除对象存储中的二进制对象；是否产生孤立对象取决于是否存在其它清理机制。
- **多角色关联表的删除**：删除歌曲的路由未显式删除原唱、合唱、词曲等关联表行；是否依赖数据库外键级联或会话配置，需结合运行环境确认；若外键未级联，删除可能失败并表现为错误响应（本规范不承诺具体 HTTP 状态码）。
- **筛选选项响应中的「专辑」字段**：当前实现向「专辑」字段填入的是从歌曲汇总的合唱艺人名字集合，与「专辑名」语义不一致；调用方若以字段名理解专辑列表可能产生误解。
- **存储路径搬迁失败**：搬迁过程中单个对象复制失败时，实现跳过该条并继续处理其余文件，且不中止本次保存事务；不在本条规范中承诺「全部文件必然迁至新键」。
- **前端参数拼装**：列表与筛选在浏览器中的具体请求形态未在本规范中约束。
- **专辑年份字段**：`albums.year` 已自数据模型移除；发行时间以歌曲 `release_date` 为准。
